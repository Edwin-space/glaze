# Glaze bundled media tools

Put local compatibility tools here when validating MKV/WebM/AVI playback:

```text
Tools/ffmpeg
Tools/ffprobe
```

The Xcode post-build phase copies executable files from this directory into:

```text
Glaze.app/Contents/MacOS/
```

Runtime lookup order:

1. Bundled helpers under `Contents/MacOS`
2. Legacy bundled locations under `Contents/MacOS/Tools` and `Contents/Resources/Tools`
3. Homebrew/system locations such as `/opt/homebrew/bin`

Distribution rules:

- Use an LGPL-compatible FFmpeg build for App Store candidates.
- Do not use builds configured with `--enable-gpl` or `--enable-nonfree` for the default App Store build.
- Keep binary provenance, license text, source offer, and build flags documented before shipping.
- Do not commit downloaded FFmpeg binaries until the license and distribution plan are explicitly approved.

Local LGPL build:

```bash
./script/build_lgpl_ffmpeg_tools.sh
```

The script downloads official FFmpeg source, configures it without GPL/nonfree flags, builds `ffmpeg` and `ffprobe`, and places the local validation binaries in this directory. The generated binaries and build note are ignored by Git.

## VLC (`Tools/vlc`)

`Tools/vlc/lib` (`libvlc`/`libvlccore`) and `Tools/vlc/plugins` back the native VLC playback engine (`Sources/GlazeMac/Core/Media/NativeVLCLibrary.swift`).

License status (curated 2026-08-10, see `docs/16_foundation_redesign_audit.md` §2.3 and `Tools/vlc/LICENSE-THIRD-PARTY.md`):

- `libvlc`/`libvlccore` themselves are LGPL-2.1 and compatible with App Store distribution. VideoLAN's own guidance: "The App Store Terms of Service are incompatible with GPLv2, while distribution under LGPLv2.1 is absolutely permitted."
- `Tools/vlc/plugins` originally shipped as a full desktop VLC.app extraction (339 plugins). Every plugin was checked against its own embedded license declaration (`strings <plugin>.dylib | grep "Licensed under the terms of"`, plus FFmpeg's own embedded license string for the 4 FFmpeg-derived plugins) — **74 GPL-only or unnecessary (streaming-server/VLC-own-interface/niche) plugins were removed; 265 LGPL-confirmed plugins remain.** Full removal list and rationale: `Tools/vlc/LICENSE-THIRD-PARTY.md`.
- `Tools/vlc/LICENSE-THIRD-PARTY.md` now provides the LGPL license notice/attribution that was previously missing.

Distribution rules:

- The current `Tools/vlc/plugins` set (265 plugins, curated 2026-08-10) is believed LGPL-only based on each plugin's own embedded declaration — verified via build+playback regression test (MP4/H.264+AAC and MKV/HEVC 5.1 both confirmed playing after the cleanup).
- Not a substitute for legal review: `LICENSE-THIRD-PARTY.md` flags two residual uncertainties (`liba52_plugin`, `liblive555_plugin`) worth a license professional's look before actual App Store submission, and any future `Tools/vlc` update should be re-scanned with the same method before shipping.

## Opening this project in Xcode

This used to be a bare Swift Package opened via `Package.swift`, which gave Xcode's reduced "package" UI (no Build Phases tab, limited Signing & Capabilities). It's now a **real Xcode project**, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` at the repo root — that YAML file is the actual source of truth, `Glaze.xcodeproj` itself is generated output and is gitignored.

Structure:

- `Packages/GlazeCore` — the platform-independent core (media/subtitle models, AI subtitle generation) as its own local Swift package. No AppKit/AVKit dependency, so this is also the thing a future iOS or tvOS app target (see `docs/06_platform_global_expansion_plan.md`) would depend on — adding one later is a new `targets:` entry in `project.yml` pointing at this same package, no code changes needed here.
- `Sources/GlazeMac` — the macOS app's source, wired as the `GlazeMac` target's source folder.
- `Packaging/Info.plist` — single source of truth for the app's `Info.plist`, referenced directly via the `INFOPLIST_FILE` build setting (not xcodegen's plist-generation feature — that overwrites the file it's pointed at, which is not what we want for a hand-maintained plist).
- `Packaging/Glaze.entitlements` — App Sandbox entitlements (`app-sandbox`, `files.user-selected.read-write` for the Open Video/Import Subtitle panels, `network.client` for WhisperKit's model download). Applied only to the **Release** configuration (see `project.yml`); Debug builds stay unsandboxed on purpose for a fast dev cycle. **Verified 2026-08-10**: built Release with these entitlements and confirmed via `lldb` attach that VLC's `dlopen` of its bundled dylibs still succeeds under App Sandbox (see `docs/16_foundation_redesign_audit.md` §3.4 for the caveat about Distribution-signed Archive builds, which weren't tested this way).
- `Packaging/GlazeHelper.entitlements` — minimal sandbox inheritance entitlements for the bundled `ffmpeg` and `ffprobe` command-line helpers. Release builds sign each helper individually with the target signing identity and hardened runtime before Xcode signs the outer app.
- `Sources/GlazeMac/Resources/Assets.xcassets/AppIcon.appiconset` — real app icon artwork, exported from the Figma brand guideline at all required sizes.
- `script/xcode_vlc_stage.sh` — a Run Script build phase (wired in `project.yml`) that copies `Tools/vlc` into resources, stages `ffmpeg`/`ffprobe` under `Contents/MacOS`, signs the Release helpers for sandbox inheritance, and patches the VLC dylibs' load paths.
- `script/verify_app_sandbox_signing.sh <Glaze.app>` — fails if the app or either bundled helper is missing its required App Sandbox entitlement. Run it against the app inside every new Archive before uploading.

### First-time setup / regenerating the project

```bash
xcodegen generate   # reads project.yml, (re)writes Glaze.xcodeproj
open Glaze.xcodeproj
```

Run this again any time `project.yml` changes (`script/build_and_run.sh` also does this automatically before every build). From here it's a fully native Xcode "Application" project: Build Phases, full Signing & Capabilities, asset catalog drag-and-drop, the works.

### Steps that need your Apple ID (I can't do these for you)

1. Select the **GlazeMac** scheme (top of the Xcode window).
2. Go to the target's **Signing & Capabilities** tab, sign in with your Apple ID, and pick or create a Team. Xcode will register the bundle ID (`com.edwin.glaze`) automatically the first time you build with a Team selected.
3. When ready to ship: **Product ▸ Archive ▸ Distribute App ▸ App Store Connect**. If no App Store Connect app record exists yet for `com.edwin.glaze`, Xcode prompts you to create one as part of this flow.

None of this can be scripted or automated on your behalf — it requires your account credentials.
