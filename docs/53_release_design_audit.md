## 판정

**현재는 제출 보류.** 이번 실행 화면으로 확인한 UI 결함과 제출 전 확인이 남은
항목을 구분한다. 자동 테스트 성공을 디자인 완성이나 전체 접근성 적합으로
해석하지 않는다. 이번 작업은 검수와 재현 기반 추가이며 제품 UI를 바꾸거나
App Store 심사를 신청하지 않았다.

공개 홈페이지·지원·개인정보·약관 URL은 이번에도 모두 HTTP 404였다. Apple은
완성된 메타데이터와 작동하는 URL, 실제 기기 안정성 확인을 요구한다.
[App Review Guidelines 2.1 / 5.1.1](https://developer.apple.com/app-store/review/guidelines/)

## 방법과 증거 규칙

화면별 원본과 장점·문제·제한은 [실행 화면 갤러리](audits/2026-11-09-release-design/README.md)에
흐름 순서로 함께 보관한다. 제품 코드 기준은 `5a134f2`이며 이번 변경은 테스트·문서뿐이다.

- 사용자 승인 XCUITest로 현재 작업 트리의 앱을 조작·캡처했다.
- 실물 iPhone은 iPhone 13 mini만 사용했다. iPhone 17 Pro와 실물 Apple TV에는
  설치하거나 테스트하지 않았다.
- 시뮬레이터와 Mac의 Debug 화면 검수다. 배포 서명된 Release의 기능·샌드박스
  검증, 최소 지원 OS 검증, VoiceOver 적합 판정과 별개다.
- 개인 영상 대신 Sintel 공개 샘플의 120초 구간 두 개를 사용했다. 로컬 재생
  배치 확인용이며 NAS 연속 재생·번역·전체 코덱 검증을 대신하지 않는다.
- 전환 도중 화면, 전체 Mac 데스크톱, 개인 서버 주소가 노출된 캡처는 공개
  증거에서 제외했다. 통과 캡처는 직접 열어 확인한 원본만 보관한다.
- 재현: [캡처 테스트 안내](../Tests/RELEASE_DESIGN_AUDIT.md).

검수 기준은 [Apple HIG Layout](https://developer.apple.com/design/human-interface-guidelines/layout),
[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)의
적응형 배치·확대 텍스트·식별 가능한 조작·대비 원칙이다. 스크린샷으로 실제
읽기 순서, 전체 터치 영역, 대비 설정별 동작을 모두 입증할 수는 없다.

## 확인된 항목

### UI-00 · 최초 재생 안내의 가로 화면 잘림 · P1

작은 iPhone 시뮬레이터에서 첫 영상을 연 뒤 가로로 돌리면 안내 카드의 제목과
‘Got it’ 버튼이 화면 밖으로 나간다. 일반 재생 화면의 버튼 잘림과 다른 문제다.
화면 전체를 캡처해 앱 영역 캡처의 잘못된 회전 좌표와도 분리했다.

- 영향: 처음 사용자가 가로 화면에서 안내를 끝내기 어렵다. 세로 회전은 우회일
  뿐이며 정상 완료 방식으로 삼으면 안 된다.
- 원인 확인: `IOSGestureGuideView`는 긴 고정 VStack이고, 플레이어의 오버레이에
  세로 스크롤·가용 높이 제한이 없다. 설정의 안내 페이지는 이미 스크롤을 쓴다.
- 수정안: 제목/닫기와 완료 액션은 안전 영역 안에 유지하고 설명만 스크롤한다.
  작은 화면에서 텍스트를 줄이거나 안내를 자동 생략하지 않는다.
- 완료 기준: 가로/세로·확대 글자에서 제목과 완료 버튼이 보이고, 마지막 설명까지
  스크롤·VoiceOver로 접근 가능. 실물 13 mini에서 별도 재확인.
- 공수: 작음~중간. 기존 안내 컴포넌트의 표시 컨테이너 수정이며 플레이어 재설계는 불필요.

### UI-01 · macOS 진단 설정의 위치와 위계 불일치 · P2

다른 설정 페이지는 상단 제목·설명·카드의 동일한 시작선을 사용한다. 진단만
제목 없이 폼 전체가 세로 중앙에 놓인다. 페이지를 바꿀 때 읽기 시작 위치가
튀고, 같은 설정 앱의 일부로 인식하기 어렵다.

- 기획: 진단 활성화 / 보고서 준비·공유 / 데이터 삭제를 구분한다.
- 디자인: 기존 SettingsPage 상단 제목·설명과 같은 여백·최대 폭을 재사용한다.
- 개발: 기존 설정 페이지 컨테이너를 공통화하고 진단 본문만 넣는다. 기능은 유지.
- 완료 기준: 최소 창 크기·영문·한국어에서 제목 시작선이 다른 설정과 같고,
  생성 중·완료·실패·삭제 후 상태를 키보드로 구분할 수 있다.
- 공수: 작음. 설정 공통 컨테이너 재사용.

### UI-02 · 앱 표시 언어와 언어명 표기의 혼용 · P2

영문 앱 UI에서 기본 언어·내장 자막·오디오 트랙이 ‘영어’, ‘독일어’ 등 한국어로
나온다. iPhone/iPad 설정과 자막 시트, tvOS 온보딩·설정에서 확인했다. 한국어 UI는
이번 캡처에서 자연스럽게 표시됐다.

- 재현 조건: 앱 언어만 `AppleLanguages=(en)`으로 바꾸고 호스트의 한국어 지역
  설정은 유지. 영어 시스템 전체에서 항상 발생한다고 일반화하지 않는다.
- 원인: `IOSSubtitleLanguage`, `TVSubtitleLanguage`, iOS 트랙 이름이
  `Locale.current.localizedString(forLanguageCode:)`를 사용한다. 앱 번역 리소스가
  고른 언어와 지역 로케일이 서로 다른 경로를 탄다.
- 수정안: 앱의 실제 지원 표시 언어로 만드는 공통 언어명 포매터를 사용한다.
  한국어·영어와 미지원 언어의 영어 폴백을 함께 테스트한다. 언어 **코드**와
  자막 자동 선택 로직은 바꾸지 않는다.
- 공수: 작음~중간. 공통 포매터와 플랫폼별 호출 교체·회귀 테스트.

### UI-03 · WebDAV 입력 필드명이 입력 후 사라짐 · P2

주소 등 입력 필드가 placeholder만 사용한다. URL을 넣으면 ‘Address’라는 필드명이
사라진다. 작은 화면에서 입력 정보를 다시 확인하기 어렵고 빈 placeholder도 흐리다.
URL 키보드와 키보드 위의 연결 버튼은 이번 세로 화면에서 가리지 않았다.

- 수정안: 이름/주소/사용자 이름/암호에 지속적으로 보이는 라벨을 둔다. 예시 URL은
  보조 설명으로 남기고, 잘못된 URL·인증 실패를 필드와 연결해 안내한다.
- 접근성: 실제 VoiceOver 이름·입력 순서와 대비 증가는 별도 검증한다. 보이는
  placeholder가 있다고 접근성 라벨까지 충분하다고 판단하지 않는다.
- 공수: 작음. 연결 저장 모델·프로토콜 변경 없이 폼만 정리.

### UI-04 · 네트워크 빈 화면의 다음 행동 약함 · P2

iPhone의 ‘No servers added yet’ 아래에는 추가 방법이 없고 우측 상단 `+`만 있다.
처음 NAS를 연결하는 사람에게 빈 상태와 다음 행동의 연결이 약하다. 아이콘 자체가
깨지거나 추가 버튼이 동작하지 않는 결함은 아니다. TV 홈은 연결 CTA를 명시하고 있다.

- 수정안: 빈 상태 안에 ‘서버 추가’ 버튼과 지원 연결 방식 한 줄을 둔다. 기존 `+`
  버튼과 같은 진입점을 재사용하고 온보딩을 반복시키지 않는다.
- 공수: 작음. 기존 추가 액션 재사용.

### UI-05 · 주요 시작 버튼의 낮은 대비 · P2 / 접근성

iPhone 환영 화면은 앰버 바탕에 흰 Start, TV 환영 화면의 포커스된 Continue는
밝은 회색 바탕에 앰버 글자로 표시된다. 원본 PNG의 대표 단색 영역을 표본 추출하고
sRGB 상대 휘도로 계산하면 iPhone `#FFFFFF / #E8963D`는 **약 2.37:1**,
TV 앰버/밝은 회색은 **약 1.4:1**이다. 둘 다 큰 글자 기준 3:1에도 못 미친다.
안티앨리어싱 가장자리는 표본에서 제외했다. 전체 상태의 접근성 적합 판정은 아니다.

- 수정안: 포커스/선택/비활성 상태별 전경·배경 색 계약을 정하고, 밝은 포커스에서는
  충분히 어두운 전경색을 사용한다. 시스템 포커스 확대·리모컨 동작은 유지한다.
- 완료 기준: Apple HIG 대비 기준을 측정하고, 대비 증가 설정과 실물 TV에서 확인.
- 공수: 작음. 버튼 상태 스타일의 국소 수정.

### UI-06 · Matroska 파일을 WEBM으로 표시 · P2 / 정보 정확성

Mac 정보 패널에서 `AuditSample1.mkv`를 WEBM으로 표시했다. 샘플의 EBML 헤더에는
`matroska`가 있고 ffprobe의 포맷 응답은 `matroska,webm`이다. 이는 별칭 목록이지
‘webm으로 확정’이라는 응답이 아니다.

- 코드 확인: `FFprobeMediaInspector.displayContainer`가 목록에서 `matroska`를 제외한
  첫 이름을 고르기 때문에 WebM으로 바뀐다.
- 수정안: 공용 demuxer 별칭과 실제 컨테이너를 구분한다. 확정할 수 없다면
  ‘Matroska / WebM’처럼 정직한 계열 표기를 사용한다. 실제 Matroska/WebM 샘플로
  분리 회귀 테스트한다.
- 공수: 작음~중간. 포매터 수정과 두 컨테이너의 검사 결과 회귀 테스트.

Mac 자막 목록의 `Embedded Subtitle · DE`, `SUBRIP` 같은 표기도 사람이 읽는
언어명/출처보다 구현 메타데이터가 앞선다. UI-02 언어명 계약을 Mac까지 확장하고
포맷 정보는 필요할 때만 보조 정보로 제공하는 편이 일관된다.

## 코드에서 확인한 추가 위험 — 화면 결함 확정과 구분

- 자막 Delay의 `−/+`는 `.plain` 이미지 버튼이고 명시적 ‘자막 지연 줄이기/늘리기’
  접근성 이름·최소 터치 영역 지정이 없다. 작은 아이콘은 화면에서도 확인되지만
  **실제 hit frame을 측정하지 않았으므로 44pt 미달로 단정하지 않는다.** VoiceOver
  의미와 터치 영역을 측정한 뒤 보완한다.
- 상단 컨트롤 폭의 정적 계산에서 우려했던 작은 iPhone의 잘림은 실제 세로/가로
  재생 캡처에서는 재현하지 못했다. 이를 확인된 결함으로 올리지 않는다.
- iPad 설정은 전체 폭 List다. 제한된 폭의 Form이 읽기에는 유리할 수 있으나
  이번 화면에서 기능을 막는 겹침은 없었다. 낮은 우선순위의 밀도 개선 후보다.
- Mac 정보 패널 전환 뒤 검은 프레임이 1회 캡처됐지만 재실행·즉시/3초 대기·
  재생 재개 후에는 정상 프레임이었다. 지속되는 검은 화면 버그로 확정하지 않는다.

## 자동 실행 기록

- iPhone 시뮬레이터: 7개 캡처 시나리오 통과. 회전 캡처를 `XCUIScreen`으로 바꾼 뒤
  재생·최초 안내 2개를 다시 통과. **테스트 성공 중에도 UI-00은 화면에 존재했다.**
- iPad 시뮬레이터: 온보딩·설정·재생 3개 통과, 전체 화면 회전 캡처 재생 1개 재통과.
- tvOS 시뮬레이터: 온보딩, 홈→설정 2개 통과.
- Mac: 시작/설정 1개와 URL 열기/재생/패널 1개 통과, 정보 패널 지연/재생 재개 재확인.
- 실물 iPhone 13 mini: 온보딩 1개 통과. 다른 물리 iPhone에는 설치하지 않았다.
- 테스트 인프라 실패: 최초 iOS 실행의 background assertion, Mac의 파일 인수 실행·
  별도 NSOpenPanel 접근 실패. 파일 전달은 공개 XCTest `openURL` API로 검수했다.
  이 환경 실패들을 제품 UI 결함 수에 넣지 않는다.
- Xcode의 종료 후 `simctl diagnose`가 지연돼 **자신이 시작한** 해당 진단 하위
  프로세스만 종료하고 결과 번들을 정상 기록했다. 이후 `-collect-test-diagnostics never`를
  사용했다. 앱의 사용자 진단 로그 기능·데이터는 변경하지 않았다.
- raw `.xcresult`와 기기 식별 정보는 `/tmp/glaze-diagnostics-{ui,mac,tv,build}`에만
  남긴다. 공개 보고서에는 직접 확인한 개인정보 없는 PNG만 포함한다.
