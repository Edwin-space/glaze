# 아이폰·아이패드 정식 출시 준비 — 지금 상태와 남은 일

작성일: 2026-10-06 · 대상: iOS/iPadOS

## 1. 이번에 넣은 것 — 최초 실행 안내

없던 것이다. 앱을 처음 열면 빈 폴더와 `네트워크`라는 탭이 있을 뿐, 영상이 어떻게
들어오는지 화면 어디에도 쓰여 있지 않았다. 그것은 해보면서 알아낼 일이 아니다.
영상을 넣는 두 가지 방법(파일 앱, 같은 네트워크의 서버)이 모두 글레이즈 **바깥에서**
시작하기 때문이다.

- **첫 실행 카드** (`IOSWelcomeView`): 네 줄 — 영상 넣기, NAS, 자막, 손동작 — 과
  "영상은 이 기기 밖으로 나가지 않는다"는 한 문장. 넘겨야 하는 슬라이드가 아니라
  한 화면이고, `시작하기` 하나로 끝난다
- **손동작 안내** (`IOSGestureGuideView`): 처음 연 영상 위에 한 번. 더블탭·스와이프·
  길게 누르기·막대 끌기는 화면에 흔적을 남기지 않는 동작이라 — 그래서 좋은 동작이고,
  그래서 아무도 발견하지 못한다 — 글로 한 번은 말해야 한다. **읽는 동안 영상은 0초에
  멈춰 기다린다.** 안내를 읽는 사이에 오프닝이 지나가면 안내가 아니라 방해다
- **설정 › 도움말**: 둘 다 다시 볼 수 있다. 한 번만 볼 수 있는 안내는 안 쓴 것과 같다

문구는 `ios.welcome.*`, `ios.guide.*`, `ios.settings.help*` (한/영).

## 2. 아이콘 배치 점검

### 고친 것

| 위치 | 전 | 후 |
|---|---|---|
| 목록의 NEW 표시 | 제목 옆 캡슐 — 제목 길이에 따라 줄마다 다른 자리 | 줄 맨 앞 고정 칸의 7pt 점 (`docs/49`) |
| 첫 실행 카드의 글머리 | — | 32pt 고정 칸. 글리프 네 개가 각각 다른 왼쪽 선을 만들지 않게 |

### 남은 것 — 재생 화면 위쪽이 가장 혼잡하다

오른쪽에 원형 버튼이 다섯~일곱 개 붙어 있고, 성격이 셋으로 갈린다.

| 묶음 | 버튼 |
|---|---|
| 화면 상태 | 잠금, 채우기/맞추기, 가로/세로 |
| 재생 | 배속(1×), 재생목록 |
| 내용 | 자막·음성 |

생김새가 전부 같은 원이라 묶여 보이지 않고, 하나씩 읽어야 한다. 게다가 자막 버튼
(`captions.bubble`)이 여는 것은 이름이 `ios.player.settings`인 시트다. 아이콘은 자막이라
말하고 이름은 설정이라 말한다.

제안(아직 구현 안 함):
- 화면 상태 세 개는 하나의 `…` 메뉴로 접는다. 영상을 보는 동안 자주 쓰는 것이 아니다
- 위쪽에 남는 것은 닫기 · 배속 · 자막 세 개
- 자막 버튼의 이름을 자막으로 맞춘다
- **재생 화면에서 영상 정보로 가는 길**도 이 메뉴에 넣는다 (`docs/49`의 남은 것)

## 3. 앱 스토어 등록 이미지

- 필수 크기는 아이폰 **6.9형 1320×2868**이다. 가지고 있는 아이폰 17 Pro는 6.3형
  (1206×2622)이라 그대로는 쓸 수 없다. 6.9형 시뮬레이터로 찍으면 **실제 픽셀 크기**로
  나오므로 작은 화면을 늘린 그림이 아니다. 애플도 시뮬레이터 캡처를 받는다
- 상태 표시줄은 `simctl status_bar override`로 9:41 · 신호 가득 · 충전 100%로 맞췄다
- 합성 스크립트: `Tools/make_store_images.py` — 실제 캡처 위에 한국어 문구만 얹는다
  (근거 없는 목업이나 과장 없음)
- **막는 것 하나:** 지금 테스트에 쓰는 `testmedia.mkv`는 저작권 있는 작품이다.
  등록 이미지에 그 장면과 배급사 로고가 그대로 찍힌다. 이번에 만든 합성본은
  **저장소에 넣지 않고 버렸다.** 최종본은 블렌더 재단 공개 영화 같은 CC 라이선스
  영상으로 다시 찍어야 한다 (`docs/45` §6과 같은 기준)
- NAS 주소·서버 이름·개인 폴더 이름이 보이지 않게 하는 규칙도 그대로 적용한다

## 5. 검증 중 발견한 결함 — 막대를 천천히 끌면 2배속이 걸린다

등록 이미지용 캡처에서 섬네일과 `2× 속도` 표시가 **동시에** 찍혔다. 터치 레이어가
화면 전체 높이를 차지하고 조작 막대 아래에도 깔려 있어서, 재생 막대를 천천히 끄는
동작이 "좌·우 길게 누르기"로도 읽힌다. 장면을 찾는 중에 영상이 2배속으로 달리면
플레이어가 사용자와 싸우는 것이다.

고침: 끄는 중(`isScrubbing`)에는 길게 누르기를 시작하지 않고, 손가락이 막대에
닿는 순간 이미 걸려 있던 배속은 푼다. **빌드는 통과했으나 화면으로 재확인하지는
못했다** — 다음 실기기 테스트에서 확인할 것.

## 부록. 실기기 검증 (2026-10-08, 아이폰 17 Pro, 빌드 14)

### 실기기를 조작하는 방법

`devicectl`은 화면을 **찍을 수는 있어도 만질 수는 없다** — `device capture screenshot`은
있고 입력 명령은 없다. 그래서 UI 테스트 타깃(`Tests/GlazeiOSUITests`)을 만들었다.
맥에서 `xcodebuild test`로 실제 폰을 조작하고, 각 단계의 스크린샷을 결과 번들에서
꺼낸다. 릴리스 빌드에 영향이 없도록 `GlazeiOS` 스킴이 아니라 별도 스킴에 둔다.

첫 빌드에는 `-allowProvisioningUpdates -allowProvisioningDeviceRegistration`이 필요하다
(기기가 개발자 계정에 등록되어 있지 않다).

### 테스트는 사용자의 영상을 열지 않는다

처음 쓴 테스트는 폴더의 **첫 번째 영상을 자동으로 열었고**, 그것은 기기 주인의 개인
영상이었다. 스크린샷에 그대로 찍혔고 전부 즉시 폐기했다.

지금은 테스트가 **직접 기기에 넣은 파일 하나만** 연다.

```bash
xcrun devicectl device copy to --device <기기> --domain-type appDataContainer \
  --domain-identifier com.edwin.glaze \
  --source "test file/testmedia.mkv" --destination Documents/glaze-uitest-sample.mkv
```

그 이름의 행이 없으면 테스트는 실패하고 끝난다. 찾아 들어가지 않는다.
네트워크 테스트는 서버 안의 파일을 열 수밖에 없으므로 **스크린샷을 한 장도 남기지
않는다.** 시간과 크래시 여부만 기록한다.

### 끄는 중의 화면을 찍는 법

제스처는 끝날 때까지 테스트 스레드를 붙잡는다. XCUITest가 찍는 스크린샷은 손가락을
뗀 **뒤**에 찍히고, 그때는 섬네일이 이미 사라져 있다 — 이 기능을 확인할 수 없었던
이유다. 맥에서 `devicectl`로 동시에 찍는 방법도 두 번 실패했다(타이밍이 맞지 않고
폰이 잠들었다).

해법은 제스처를 시작하기 **전에** 다른 큐에 스크린샷을 예약하는 것이다. 테스트
스레드는 끌고 있고, 예약된 쪽은 화면만 읽는다.

### 막힌 것 — 자동 잠금

폰이 1분 남짓마다 잠긴다. 잠기면 테스트 러너의 연결이 끊어지고
(`The connection was invalidated`), `devicectl`도 거부한다
(`not able to fulfill the requested usage assertion requirements`).
NAS 테스트 세 번 중 두 번이 이것으로 끝났다.

**설정 › 디스플레이 및 밝기 › 자동 잠금 → 안 함**으로 두고 실행해야 한다.

### 거짓 통과 두 건 — 단언을 고쳤다

- TMDB 테스트가 검색어 칸을 비우지 못해 `glaze-uitest-sampleParasite`를 검색했고,
  당연히 아무것도 찾지 못했다. 그런데 `검색 결과` 머리말은 **결과가 없어도 뜨므로**
  테스트는 통과했다. 지금은 "맞는 작품을 찾지 못했습니다"가 없을 것과 후보가 둘 이상일
  것을 함께 확인한다
- NAS 테스트가 "이동 뒤 재생 화면이 사라졌다"로 실패했는데, 컨트롤이 5초 뒤 스스로
  사라진 것이었다. 앱은 멀쩡했다. 지금은 컨트롤을 다시 부른 뒤 **재생 위치가 실제로
  움직였는지**까지 확인한다

### 등록 이미지

실기기는 6.3형 **1206×2622**다. 앱 스토어가 요구하는 아이폰 크기는 6.9형
**1320×2868**이라 실기기 캡처로는 규격을 맞출 수 없다. 같은 코드의 6.9형
시뮬레이터로 찍어야 한다. 그리고 등록 이미지에 쓸 영상은 CC 라이선스 작품이 따로
필요하다(위 3절).
