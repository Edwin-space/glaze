# Apple TV — 검증 상태 기록

작성일: 2026-09-06

## 이 문서의 성격

애플TV 작업을 잠시 멈추고 iOS/iPadOS로 넘어가면서, **무엇이 확인됐고 무엇이 남았는지**를
적어둔다. 나중에 돌아왔을 때 같은 것을 다시 확인하지 않기 위해서다.

## 확인된 것

| 항목 | 방법 | 결과 |
|---|---|---|
| 실기기 설치·실행 | Apple TV 4K 3세대(tvOS 26.6), `devicectl` | 성공. 서명은 Apple Development(Team JBN99YZ7KN) |
| DLNA 서버 발견 | 실기기 | Synology(The-ifs)를 SSDP로 찾음 |
| 상단 탭바 구조 | 시뮬레이터 | 홈/영화/TV 프로그램/미디어 소스/설정 + tvOS 검색 탭 |
| 시리즈 묶기 | 시뮬레이터, DLNA 실데이터 | 낱개 에피소드 45개 → 프로그램 4개. 시즌 선택·에피소드 목록 동작 |
| 시리즈 상세 화면 | 시뮬레이터 | 포스터·시즌 칩·에피소드 행·재생 버튼 |
| VLCKit 재생 경로 | 빌드 | 정적 링크, tvOS 빌드 성공 |

## 확인되지 않은 것 — 남은 숙제

### 1. 포스터가 실제로 그려지는가

**가장 중요한 미확인 항목.** 맥이 NAS에 써둔 `-poster.jpg`를 애플TV가 읽어 셀프에 그리는지
끝까지 보지 못했다.

- 실기기 로그로 확인된 사실: 앱이 **저장된 WebDAV 연결 0개** 상태로 DLNA에 폴백하고 있었고,
  DLNA에는 아트워크가 없다. 즉 포스터가 안 나온 것은 당연한 결과였고 아트워크 코드의
  결함 여부는 아직 모른다.
- 그 과정에서 두 개를 고쳤다(아래 "고친 것" 참고).
- **다음에 할 일:** NAS 연결 후 홈 화면에서 포스터가 뜨는지 확인. 안 뜨면 콘솔을 붙여
  `TVArtworkLoader`의 요청 성패를 본다.

### 2. 4K/HDR/5.1ch 재생 안정성

`MediaCachingPolicy`(원격 3초 버퍼)를 tvOS에도 넣었지만 **실기기에서 재생해보지 않았다.**
맥에서는 같은 파일(9.25GB 4K HDR10+ DV)이 안정적으로 재생되는 것을 확인했다.

### 3. 평문 HTTP NAS 연결

`NSAllowsLocalNetworking = true`가 어디까지 허용하는지 확정하지 못했다. 시뮬레이터에서
`http://127.0.0.1`은 막혔다(루프백은 사설 IP가 아니다). WebDAV를 평문 5005로 쓰는 사용자가
애플TV에서 연결되는지는 실기기 확인이 필요하다. 사용자의 NAS는 HTTPS(5006)라 현재는
막히지 않는다.

### 4. 스캔 중 앱 종료

폴더를 읽다가 앱이 죽는 현상이 보고됐다. 원인을 **로그로 확인하지 못했다** — 기기 크래시
리포트가 맥으로 동기화되지 않았고 `devicectl`에 가져오는 명령이 없다. 공유 전체를 훑던
문제를 고쳤으므로 재현되지 않을 가능성이 높지만, **원인을 짚었다고 단정하지 않는다.**
재현되면 콘솔을 붙인 채로 종료 사유를 받는다.

## 이 과정에서 고친 것

- **온보딩에서 추가한 NAS가 앱에 보이지 않음.** 두 화면이 각자 연결 저장소 사본을 들고
  있어 한쪽의 저장이 다른 쪽에 반영되지 않았다. `WebDAVConnectionStore.reload()` 추가.
- **포스터 자격증명이 빈 값.** 실행 시점에 "첫 번째 저장된 연결"에서 한 번만 읽는데 그때는
  연결이 없어서, 모든 포스터를 인증 없이 요청하고 있었다. 라이브러리가 연결을 채택하는
  시점에 넘기도록 바꿨다.
- **NAS 전체를 훑던 문제.** WebDAV 루트는 모든 공유다. 연결마다 라이브러리 폴더를 한 번
  묻고 거기서만 스캔한다.
- **NAS 시스템 폴더.** `@eaDir`(시놀로지 썸네일), `#recycle` 등을 건너뛴다.

## 재개할 때 첫 단계

1. 애플TV에서 NAS를 추가하고 폴더로 `Media`를 고른다
2. 홈에서 포스터가 뜨는지 본다 — 이것 하나로 위 1번이 닫힌다
3. 4K 파일을 재생해 2번을 닫는다
