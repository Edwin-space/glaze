# 사용자 플로우

작성일: 2026-06-18  
프로젝트명: 글레이즈 / Glaze

## 문서 목적

이 문서는 글레이즈의 핵심 사용자 흐름을 정의한다. 기능 구현 전에 사용자의 행동, 앱의 판단, 표시할 안내, 예외 처리를 정리해 잘못된 흐름을 조기에 발견하고 수정하기 위한 문서다.

이 문서는 이후 사용자 가이드, FAQ, 온보딩, 도움말 문서의 기반이 된다.

## 플로우 설계 원칙

- 사용자가 요청하지 않은 AI 작업은 시작하지 않는다.
- 재생 흐름을 먼저 보장하고, 자막 생성은 제안으로 제공한다.
- 자막이 없다는 사실은 숨기지 않지만 감상을 방해하지 않는다.
- 저장 위치 선택은 자막 생성 요청 시점에 묻는다.
- 시스템 언어와 영상 언어를 고려해 제안을 다르게 한다.
- 오류는 조용히 실패하지 않고 다음 행동을 제시한다.

## Flow 1. 첫 실행

### 목표

사용자가 앱을 처음 열었을 때 무엇을 할 수 있는지 즉시 이해한다.

### 흐름

1. 앱 실행
2. 시스템 언어 확인
3. 한국어/영어 UI 적용, 미지원 언어는 영어 fallback
4. 빈 플레이어 화면 표시
5. "영상 열기" 액션 제공

빈 화면도 어두운 미디어 스테이지를 유지하며 SF Symbol, 짧은 설명, Liquid Glass 기본 액션만 표시한다. 영상이 열리기 전 툴바에는 "영상 열기"만 표시하고, 영상이 열린 뒤 파일명·자막·보조 패널 액션을 추가한다.

### 표시 텍스트

- 영상을 놓고 바로 재생하세요
- 어떤 포맷이든 열어보세요. 자막이 없을 때만 글레이즈가 조용히 도와드립니다.

### 실패/예외

- localization 로딩 실패 시 영어 fallback

## Flow 2. 로컬 영상 열기

### 목표

사용자가 로컬 파일을 선택하고 바로 재생한다.

### 흐름

1. 사용자가 "영상 열기" 선택 또는 플레이어 내부로 영상/폴더 드래그앤드롭
2. 파일/폴더 선택 패널 표시 또는 드롭 URL 수신
3. 사용자가 영상 파일 또는 폴더 선택
4. 앱이 선택한 영상 또는 폴더의 영상 파일을 재생목록으로 구성
5. 앱이 컨테이너 기준으로 재생 엔진을 선택
6. MP4/MOV 등 macOS 네이티브 친화 포맷은 AVPlayerItem 생성
7. MKV/WebM/AVI는 네이티브 MKV 엔진 경로로 라우팅
8. 영상 재생 시작
9. 같은 폴더의 sidecar 자막 파일 감지
10. 앱이 미디어 컨테이너, AVKit 직접 재생 가능 여부, 트랙/코덱 인식 상태를 확인
11. 영상 하단 transport controls의 자막 상태 업데이트

### 감지 대상

- `movie.srt`
- `movie.vtt`
- `movie.smi`
- `movie.ko.srt`
- `movie.ko.vtt`
- `movie.ko.smi`
- `movie.en.srt`
- `movie.en.vtt`
- `movie.en.smi`
- `movie.original.srt`
- `movie.original.vtt`
- `movie.original.smi`

### 실패/예외

- 파일을 열 수 없음: 재생할 수 없는 파일이라는 메시지 표시
- AVKit 미지원 포맷: VLC/libVLC 네이티브 엔진 경로로 우선 라우팅하고 미디어 정보 패널에 기록
- MKV/WebM/AVI/MP4/MOV 등 주요 로컬 영상 컨테이너: AVKit/remux 자동 재시도 대신 네이티브 엔진 경로로 즉시 라우팅
- 네이티브 엔진 런타임 누락 시: 느린 remux 준비를 자동 실행하지 않고 번들 검증 필요 상태로 처리
- FFmpeg remux 경로: 네이티브 엔진 도입 전 검증/비상 fallback 후보로만 유지
- FFmpeg 분석 결과 비디오 코덱이 현재 AVKit 호환성 후보가 아니면 음성만 자동 재생하지 않고 비디오 코덱 미지원 안내를 표시
- FFmpeg 사용 불가 시: 호환성 처리를 위한 FFmpeg 설치/번들 필요 안내. 개발/검증 빌드는 프로젝트 `Tools/ffmpeg`, `Tools/ffprobe`를 앱 번들 리소스로 복사해 감지한다.
- 재생 아이템 실패: 현재 재생할 수 없다는 메시지를 표시하고 미디어 정보 패널에서 원인 확인
- 파일 접근 권한 없음: 권한 안내

### 현재 구현 상태

- 영상 파일/폴더 드래그앤드롭으로 재생 시작
- 선택한 영상과 같은 폴더의 추가 영상 자동 재생목록 구성
- 재생목록 패널에서 영상 전환
- 이전/다음 아이콘으로 재생목록 항목 이동
- VLC/libVLC 네이티브 엔진으로 MKV 샘플 첫 화면 표시와 재생목록 전환 확인
- 대용량 MKV는 재생 우선으로 처리하고, 미디어 정보 패널은 AVFoundation 상세 검사 대기 없이 경량 정보를 먼저 표시
- 파일 선택 직후 재생은 선택 파일 1개로 즉시 시작하고, 같은 폴더의 추가 영상은 백그라운드 스캔 완료 후 재생목록에 추가
- 단일 파일 드롭에서는 재생목록 패널을 자동으로 열지 않고, 사용자가 목록 버튼을 눌렀을 때만 표시
- 현재 영상이 끝나면 다음 재생목록 항목 자동 재생
- 재생목록 전환 또는 창 닫기 시 기존 플레이어를 정지하고 현재 아이템을 분리해 이전 음성이 남지 않게 처리
- AVKit/VLC 공통 재생/일시정지, scrubber, ±15초 탐색, 볼륨, 전체 화면 controls 구현
- Space로 재생/일시정지, 영상 더블클릭으로 전체 화면 전환
- 재생 중 2.5초 비활동 시 transport controls 자동 숨김, 포인터 이동·일시정지 시 복귀
- 승인된 후속 UX: 단일 Glass bar를 독립 시간축 + 좌측 시간·볼륨 + 중앙 ±15초·재생 + 우측 CC·PiP·전체 화면 micro controls로 분리
- 자막 생성·불러오기·언어·품질은 transport controls에 넣지 않고 Inspector/Sheet로 연결
- macOS 드래그앤드롭 직후 SwiftUI `VideoPlayer` 재구성 크래시를 피하기 위해 `AVPlayerView` 기반 재생 표면으로 전환
- `AVPlayerItem` 준비 완료 후 재생을 시작하고, 실패/대기 상태를 사용자에게 표시
- MKV/WebM/AVI/MP4/MOV 등 주요 로컬 영상 포맷을 VLC/libVLC 네이티브 엔진 대상으로 라우팅하는 재생 엔진 경계 구현
- 네이티브 엔진 런타임 누락 시 느린 remux 자동 재생 대신 번들 검증 필요 상태로 처리
- 앱 내부 미디어 정보 패널에서 컨테이너, macOS 직접 재생 가능 여부, 인식된 트랙/코덱을 표시
- MKV/고해상도/다중 트랙 파일의 실패 유형을 제품 판단 데이터로 남길 수 있는 기반 구현

## Flow 3. 자막 파일이 감지된 영상

### 목표

사용자가 별도 행동 없이 기존 자막 존재 여부를 알 수 있다.

### 흐름

1. 영상 파일 열기
2. sidecar 자막 감지
3. 한국어 자막이면 "한국어 자막 감지됨"
4. 원어/기타 자막이면 "자막 감지됨"
5. 앱은 우선순위에 따라 한국어, 원어, 기타 자막 순으로 자동 선택
6. 자막 패널에는 감지된 파일 목록과 현재 선택된 파일을 표시
7. 사용자는 자막 패널에서 다른 자막 파일로 전환할 수 있음
8. 사용자는 transport controls 또는 자막 Inspector에서 자막 표시/숨김을 전환할 수 있음

### 현재 구현 상태

- sidecar 감지와 상태 표시 구현
- 수동으로 불러온 자막 파일도 상태에 반영
- 감지된 SRT/VTT/SMI 자막 파일을 기본 파싱해 영상 위에 표시
- 여러 자막 파일 중 선택/전환 UI 구현
- 자막 표시/숨김 전환 구현
- SMI는 UTF 계열, EUC-KR, CP949 계열, ISO Latin 1 순서로 읽기 시도
- SMI의 head/style/script 노이즈 제거 및 한국어 class 우선 표시 구현

### 남은 개선 필요

- SMI의 폰트, 색상, 위치 스타일을 원본처럼 재현하는 고급 스타일 엔진
- 자막 목록 검색, 정렬, 언어 필터 같은 대량 라이브러리용 편의 기능

## Flow 3A. AI 미디어 어시스턴트

### 목표

사용자가 영상 파일을 추가했을 때, 글레이즈가 자막뿐 아니라 작품 정보와 라이브러리 정리 상태까지 준비할 수 있음을 자연스럽게 보여준다.

### 흐름

1. 영상 파일 또는 폴더 열기
2. 앱이 `MediaAsset` 생성
3. 파일명 기반 제목 후보 추출
4. 자막 준비 상태 확인
5. 툴바 패널 메뉴에서 AI 미디어 진입점 활성화
6. 사용자가 네이티브 Inspector의 AI 미디어 탭 열기
7. 앱이 작품 정보, 자막 준비 상태, 보관 위치를 표시
8. 사용자는 작품 정보 찾기, 자막 준비, 파일 정보 반영 흐름으로 진입할 수 있음

### 현재 구현 상태

- `MediaAsset` 기초 모델 추가
- 상시 노출 AI 버블 제거, 툴바 패널 메뉴와 네이티브 SwiftUI Inspector로 진입 구조 통합
- 작품 정보 매칭, 자막 준비, 파일 정보 반영 액션 자리 표시
- 원본 파일 쓰기는 기본값이 아니라 명시적 액션으로 분리

### 남은 개선 필요

- TMDB/IMDb/TVDB 등 메타데이터 공급자 추상화
- 포스터/줄거리/시즌/에피소드 매칭 UI
- sidecar metadata 저장
- 원본 파일 태그 쓰기 전 백업/권한/컨테이너 호환성 검증

## Flow 4. 자막 파일이 없는 영상

### 목표

사용자가 영상 재생을 방해받지 않으면서 자막 생성 가능성을 알 수 있다.

### 흐름

1. 영상 파일 열기
2. sidecar 자막 없음
3. 영상 하단 transport controls의 자막 액션에 "생성 가능" 상태 표시
4. 안내 문구 표시: "같은 이름의 자막을 찾지 못했습니다. 필요할 때 생성하거나 불러올 수 있습니다."
5. 사용자는 그냥 시청하거나 transport controls/툴바에서 자막 Inspector를 열 수 있다.

### 중요한 원칙

저장 위치 선택 UI는 이 시점에 띄우지 않는다.

## Flow 5. 자막 생성 요청

### 목표

사용자가 명시적으로 요청했을 때만 AI 자막 생성 흐름을 시작한다.

### 흐름

1. 사용자가 "자막 생성" 선택
2. 앱이 자막 생성 옵션 패널 표시
3. 영상 언어: 자동 감지 또는 직접 선택
4. 출력: 원어, 한국어, 원문 + 한국어
5. 모델 모드: 빠른, 표준, 고정확도
6. 저장 위치 선택: 앱 내부 또는 영상 파일 옆
7. 사용자가 확인
8. 자막 생성 작업 시작

### 플랫폼별 presentation

- macOS: 현재 영상에 종속된 trailing Inspector에서 옵션을 확인하고 생성한다.
- iPadOS regular width: 영상과 trailing Inspector를 동시에 유지한다.
- iPadOS compact width: 같은 내용을 resizable Sheet로 전환한다.
- iOS: medium detent에서 상태·핵심 옵션·기본 액션을 보여주고, large detent에서 언어·품질·저장 위치·고급 옵션을 제공한다.

### 다국어 동작 계약

- 결과 언어와 품질은 locale 독립 식별자로 저장하고, 현재 UI locale의 번역 문자열만 `Menu`에 표시한다.
- Inspector의 라벨·값 열은 고정 폭으로 잠그지 않고 번역 문자열이 40% 길어져도 줄바꿈 또는 폭 확장으로 대응한다.
- `자막 만들기`와 `자막 파일 가져오기`는 icon-only로 축약하지 않고 전체 폭 라벨 버튼으로 유지한다.
- RTL 언어에서는 Inspector의 의미 구조와 disclosure 방향을 미러링하되, 미디어 시간축과 시간 표기의 진행 방향은 플레이어 관례를 유지한다.
- 시스템 언어가 지원되지 않으면 영어로 fallback하며 자막 결과 언어 선택은 시스템 UI 언어와 독립적으로 유지한다.

어떤 플랫폼에서도 Sheet나 Inspector를 여는 것만으로 AI 작업을 시작하지 않는다. 사용자가 `자막 만들기`를 명시적으로 선택한 뒤에만 작업을 시작한다.

### 아직 미구현

- 실제 오디오 추출
- 음성 인식
- 번역
- 저장 위치 권한 처리
- 진행률 표시

## Flow 6. 시스템 언어 기반 자막 제안

### 목표

사용자 환경에 맞는 세심한 제안을 제공한다.

### 예시

시스템 언어가 한국어이고 영상 언어가 영어로 추정되며 한국어 자막이 없을 때:

1. 영상 재생 시작
2. 앱이 한국어 자막 없음 상태 확인
3. 방해가 적은 안내 표시
4. 선택지 제공:
   - 자막 생성
   - 그냥 시청
   - 자막 파일 불러오기

시스템 언어가 한국어이고 영상 언어도 한국어로 추정될 때:

- 자막 생성 제안을 최소화한다.

### 구현 시점

영상 언어 추정 기능이 필요하므로 MVP 초기에는 수동/간접 안내로 시작한다.

## Flow 7. 자막 파일 수동 불러오기

### 목표

자동 감지가 실패했거나 사용자가 별도 자막 파일을 갖고 있을 때 연결할 수 있다.

### 흐름

1. 사용자가 자막 패널 열기
2. "자막 파일 불러오기" 선택
3. SRT/VTT/SMI 파일 선택
4. 앱이 파일을 읽고 연결
5. transport controls의 자막 상태 업데이트
6. 연결된 자막 파일은 자막 패널 목록에 추가
7. 사용자는 목록에서 자막 파일을 다시 선택해 전환 가능
8. 자막 파일을 연결하면 자막 표시 상태는 다시 켜짐

### 현재 구현 상태

- SRT/VTT/SMI 파일 선택 구현
- 선택한 자막 파일을 현재 영상의 자막 상태에 반영
- 선택한 자막 파일을 기본 파싱해 영상 위에 표시
- 지원하지 않는 형식, 읽기 실패, 표시 가능한 cue 없음 오류를 구분해 안내
- 읽기 실패 시 재생은 유지하고 자막 상태만 해제
- 자막 표시/숨김 전환 구현

### 남은 개선 필요

- App Sandbox 보안 범위, 파일 이동/삭제, 권한 오류를 더 세밀하게 구분

## Flow 8. 자막 생성 실패

### 목표

실패 원인을 숨기지 않고 사용자가 다음 행동을 선택할 수 있게 한다.

### 실패 유형

- 오디오 트랙 없음
- 지원하지 않는 파일
- 모델 없음
- 저장 권한 없음
- 디스크 공간 부족
- 앱 종료 또는 작업 중단

### 표시 원칙

- 실패 원인
- 사용자가 할 수 있는 다음 행동
- 다시 시도 가능 여부

## Flow 9. 영상 내장 자막 선택과 번역 준비

1. 영상을 열면 sidecar 검사와 병행해 내장 자막 스트림을 확인한다.
2. 사용자 선호 언어의 텍스트 트랙이 있으면 캐시 SRT로 추출해 즉시 표시한다.
3. 여러 트랙이 있으면 자막 Inspector에서 언어·트랙을 선택할 수 있다.
4. 선호 언어가 없으면 다른 언어의 텍스트 트랙 cue를 번역 입력으로 준비하고 상태만 안내한다.
5. 사용자가 `자막 생성`을 명시적으로 선택하면 준비된 cue를 번역 엔진에 전달한다.
6. 이미지 기반 트랙만 있으면 지원 한계를 표시하고 음성 인식 경로를 제안한다.

내장 자막 검사·표시는 재생을 막지 않는다. 번역과 음성 인식은 자동 시작하지 않는다.

## Flow 10. 동일 네트워크 NAS/DLNA 영상 열기

1. 사용자가 네트워크 미디어 진입점을 연다.
2. 앱이 로컬 네트워크 사용 목적을 설명하고 SSDP로 MediaServer를 탐색한다.
3. 사용자가 Synology 등 서버를 선택하면 ContentDirectory의 폴더와 영상만 계층 탐색한다.
4. 영상을 선택하면 HTTP 리소스 URL을 VLC 네트워크 재생 경로로 전달한다.
5. 내장 자막은 원격 URL을 ffprobe 입력으로 검사하고, 텍스트 트랙이면 동일한 선택·번역 준비 정책을 적용한다.
6. 연결이 끊기면 재생 화면을 유지한 채 재시도 가능한 오류를 표시한다.

네트워크 미디어 시트에서 서버 탐색·폴더 이동·영상 선택 후 재생까지 연결됐다. Synology 실기기 회귀 테스트와 연결 복구는 다음 구현 단위다.
