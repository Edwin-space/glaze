# MVP 범위 및 의사결정 정리

작성일: 2026-06-18  
프로젝트명: 글레이즈

## 문서 목적

이 문서는 글레이즈 개발 착수 전에 MVP 범위와 초기 의사결정 사항을 확정하기 위한 기준 문서다. 사용자가 지금 바로 지정해야 하는 항목과, 개발 중 또는 MVP 이후로 미뤄도 되는 항목을 분리한다.

## 확정 결론

글레이즈의 첫 개발 목표는 다음이다.

> macOS Apple Silicon에서 로컬 영상을 재생하고, 자막이 없는 영상에 대해 원어 자막과 한국어 번역 자막을 생성해 저장/재사용할 수 있는 AI 영상 플레이어 MVP를 만든다.

초기 제품은 모든 기능을 포함하지 않는다. 브라우저 확장, 모바일 앱, Windows 앱, NAS/클라우드 연동, 대규모 배치 처리, 자막 편집기는 후속 확장으로 둔다.

2026-06-18 기준 사용자 확정 사항:

- MVP는 Apple Silicon 전용 버전으로 시작한다.
- 최소 지원 버전은 macOS 15로 둔다.
- UI 언어는 사용자 시스템 언어를 자동 감지한다. 한국어/영어 환경이면 해당 언어를 기본값으로 사용하고, 그 외 언어 환경에서는 영어를 기본값으로 사용한다.
- FFmpeg는 MVP 시작 시점에는 붙이지 않고 AVFoundation/AVKit으로 먼저 진행한다. 다만 고해상도 MKV 수요가 크므로 FFmpeg 도입은 늦출 수 없는 후속 핵심 과제로 둔다.
- 자막 저장 경로는 상황에 따라 다르게 처리한다.
- 배포는 App Store를 목표로 하되, 웹 배포/프리미엄 제공 방식도 동시에 고려한다.
- App Store 버전과 웹 배포/프리미엄 버전의 기능 차이는 지금 확정하지 않는다. 기능 개발 후 Apple 정책 위반 또는 심사 리스크가 있는 기능만 모아 별도 Glaze Pro/Premium 제품군으로 분리한다.
- 일부 기능은 App Store 정책상 문제가 없다면 구독형 또는 일회성 구매 풀버전 형태로 유료화할 수 있다. 다만 유료화 모델은 기능 구현 후 필터링으로 판단하며, 지금은 기능별 무료/유료/Pro 후보 태그만 관리한다.
- FFmpeg 도입 검증은 기본 Player MVP 직후 바로 진행한다.
- 자막 저장 위치 선택 UI는 최초 재생 시점이 아니라 자막 생성 요청 시점에 띄운다.
- 단, 재생 시점에 시스템 언어와 영상 언어/자막 존재 여부를 바탕으로 자막 생성 안내를 제공할 수 있다.

## MVP 포함 범위

### 1. macOS 네이티브 앱

- SwiftUI 기반 macOS 앱
- Apple Silicon 우선 지원
- 한국어/영어 UI 구조
- 기본 설정 화면

### 2. 기본 영상 플레이어

- 로컬 영상 파일 열기
- 재생/일시정지
- 탐색바
- 전체화면
- 기본 볼륨 조절
- 최근 파일 또는 현재 파일 표시

### 3. 외부 자막 로딩

- SRT 파일 로딩
- VTT 파일 로딩
- 자막 표시/숨김
- 기본 자막 스타일: 크기, 위치, 배경 정도

### 4. 단일 영상 AI 자막 생성

- 영상에서 오디오 추출
- 짧은 샘플 구간 또는 전체 영상 음성 인식
- 원어 자막 생성
- SRT 저장
- 생성 자막을 현재 영상과 자동 연결
- 진행률과 상태 표시

### 5. 한국어 번역 자막

- 원어 자막을 한국어로 번역
- 한국어 SRT 저장
- 원문만 보기
- 한국어만 보기
- 원문 + 한국어 이중 자막 보기

### 6. 자막 저장/재사용

- 자막 없는 영상 재생 또는 자막 생성 요청 시 저장 위치 확인
- 앱 내부 저장 또는 영상 파일 위치 저장 선택
- 단순 자막 번역 작업은 기본적으로 영상이 호출된 위치에 저장
- 같은 영상을 다시 열면 기존 생성 자막 자동 연결

- 자막 싱크 수동 보정

## Codex 권장 결정안

현재 상태에서 내가 권장하는 초기 결정은 다음이다.

### 앱 이름

`글레이즈`를 유지한다. 한국어로 기억하기 쉽고, 글로벌 표기는 `Glaze`로 자연스럽다.

### 초기 플랫폼

macOS Apple Silicon 전용으로 시작한다. Intel Mac 지원은 MVP 이후 검토한다.

이유:

- 온디바이스 AI 성능을 예측하기 쉽다.
- Submarine Player와 같은 직접 경쟁/레퍼런스도 Apple Silicon 중심이다.
- 초기 QA 범위를 줄일 수 있다.

### 최소 macOS 버전

macOS 15 Sequoia를 최소 지원 버전으로 둔다.

이유:

- Apple Intelligence, 최신 SwiftUI, 최신 미디어/번역 API 검토에 유리하다.
- 브라우저 확장, 온디바이스 처리, 샌드박스 정책 검토에서 최신 OS 기준이 편하다.

macOS 14 Sonoma 이하 지원은 MVP 이후 시장성과 기술 필요성을 보고 재검토한다.

### UI 언어

초기 지원 UI 언어는 한국어와 영어다. 앱 실행 시 사용자 시스템 언어를 자동으로 확인한다.

정책:

- 시스템 언어가 한국어이면 한국어 UI를 기본값으로 사용한다.
- 시스템 언어가 영어이면 영어 UI를 기본값으로 사용한다.
- 시스템 언어가 아직 지원하지 않는 언어이면 영어 UI를 기본값으로 사용한다.
- 사용자는 설정에서 UI 언어를 직접 변경할 수 있어야 한다.

개발 시작 시점부터 localization 구조를 적용한다.

### 플레이어 엔진

MVP는 AVFoundation/AVKit으로 시작한다. FFmpeg는 바로 붙이지 않는다.

이유:

- 초기 구현과 App Store 배포 검토가 단순하다.
- 먼저 자막 생성/번역이라는 핵심 가치를 검증해야 한다.
- FFmpeg를 조기 도입하면 라이선스, 번들링, 코덱 이슈가 커진다.

단, FFmpeg 도입은 늦출 수 없는 후속 핵심 과제다. 고해상도 영상이 MKV 형태로 많이 제공되기 때문에, AVFoundation/AVKit MVP가 재생 가능한 범위를 확인한 뒤 빠르게 FFmpeg 도입 여부를 판단한다.

후속 검증 항목:

- MKV 재생 지원 범위
- 고해상도/고비트레이트 영상 재생 안정성
- 오디오 트랙 추출 필요성
- FFmpeg 라이선스와 App Store 배포 영향
- 웹 배포/프리미엄 버전에서 FFmpeg 기능을 분리할 가능성

### AI 자막 생성

온디바이스 우선으로 설계한다. 다만 기술 검증 단계에서는 여러 후보를 비교할 수 있게 추상화한다.

검토 후보:

- Whisper 계열 모델
- Core ML 변환 모델
- whisper.cpp 계열
- Apple Speech/Translation API 활용 가능성

### 한국어 번역

최종 방향은 로컬/온디바이스 우선이다. 온라인 번역은 MVP 핵심값이 아니라 후순위 옵션으로 둔다. 번역 모델은 Submarine Player와 유사한 온디바이스 경험을 목표로 하되, Submarine Player 사용 경험에서 오역이 보였으므로 번역 품질 벤치마크를 별도 진행한다.

내 의견:

사용자 의견처럼 온라인 번역 옵션을 앞에 두는 것은 글레이즈의 정체성과 조금 어긋날 수 있다. 이 제품의 핵심은 Apple Silicon 온디바이스 AI와 개인정보 보호, 로컬 처리의 신뢰감이다. 따라서 MVP 기술 검증도 가능하면 온디바이스 번역 또는 Apple 시스템 API 기반 번역부터 보는 것이 맞다.

다만 온라인 번역을 완전히 배제하지는 않는다.

이유:

- 번역 품질이 제품 인상에 크게 영향을 준다.
- 온디바이스 번역 품질이나 지원 언어가 부족할 수 있다.
- 일부 사용자는 더 높은 번역 품질을 위해 온라인 번역을 선택할 수 있다.
- 글로벌 확장 시 언어별 품질 차이가 생길 수 있다.

정책:

- 기본값은 온디바이스/로컬 처리다.
- 온라인 번역은 후순위 프리미엄 또는 선택 옵션으로 검토한다.
- 온라인 번역을 사용할 경우 명확한 동의와 개인정보 안내가 필요하다.
- 자막 텍스트가 외부 서버로 전송되는지 사용자가 이해할 수 있어야 한다.

후보 접근:

- Apple Translation API 또는 Apple 시스템 번역 기능을 우선 검토한다.
- TranslateGemma 같은 번역 특화 오픈 모델을 후보에 포함한다.
- Gemma 계열의 모바일/온디바이스 최적화 모델도 후보에 포함하되, 일반 LLM보다 번역 특화 모델을 우선 평가한다.
- 한국어 중심 품질을 보려면 영어→한국어, 일본어→한국어, 중국어→한국어, 한국어→영어 샘플을 따로 평가한다.
- 자막 번역은 직역보다 문맥, 말투, 구어체, 줄 길이, 싱크 유지가 중요하므로 일반 번역 벤치마크와 별도 기준을 둔다.

### 자막 저장

상황별 저장 정책을 둔다.

정책:

- 사용자가 자막 없는 영상을 처음 재생하거나 자막 생성을 요청하는 경우, 저장 위치를 사용자에게 묻는다.
- 선택지는 앱 내부 저장과 영상 파일 위치에 저장으로 제공한다.
- 단순 자막 번역 작업은 기본적으로 번역 대상 영상이 호출된 위치에 저장한다.
- 저장 권한이 없거나 샌드박스 제한이 있으면 앱 내부 저장 또는 권한 요청으로 안내한다.
- 사용자가 선택한 저장 정책은 영상별 또는 전체 기본값으로 기억할 수 있게 한다.

이유:

- 사용자는 생성 자막 파일의 위치를 통제하고 싶어할 수 있다.
- 번역 작업은 원본 영상 옆에 결과물이 생기는 것이 자연스럽다.
- App Store 샌드박스 환경에서는 권한 요청과 fallback 정책이 필요하다.

UX 정책:

- 저장 위치 선택 UI는 자막 생성 요청 시점에 띄운다.
- 단순 재생만 하려는 사용자에게 저장 위치 선택을 먼저 요구하지 않는다.
- 재생 시점에는 자막 상태 안내만 제공한다.
- 예: 시스템 언어가 한국어이고 영상 언어가 영어로 추정되며 한국어 자막이 없으면, "한국어 자막 파일이 없습니다. 자막을 생성할까요?"를 제안한다.
- 선택지는 "자막 생성", "그냥 시청", "자막 파일 불러오기"로 둔다.
- 한국어 영상으로 추정되고 시스템 언어가 한국어이면 불필요한 자막 생성 제안을 최소화한다.

### 배포 전략

App Store 배포를 목표로 하되, 웹 배포와 프리미엄 제품군을 동시에 고려한다. 다만 App Store 버전과 웹 배포/프리미엄 버전의 기능 차이는 지금 확정하지 않는다.

정책:

- 기본 앱은 App Store 배포 가능성을 강하게 의식해 개발한다.
- App Store 정책상 제공하기 어려운 기능은 웹 배포 또는 별도 Glaze Pro/Premium 제품군으로 분리할 수 있다.
- 예: 고급 코덱, 특정 다운로드/저장 기능, 확장 기능, 프로 기능
- Movist처럼 App Store 버전과 별도 프리미엄/웹 제공 버전을 나누는 방식을 참고한다.
- 구체적인 기능 차이는 실제 기능이 구현되고 App Store 정책 리스크가 확인된 뒤 정의한다.

주의:

- App Store 버전과 웹 배포 버전의 기능 차이를 사용자에게 명확히 설명해야 한다.
- 결제 방식, 라이선스, 업데이트 경로가 복잡해질 수 있으므로 초기에 구조를 너무 과하게 나누지는 않는다.
- App Store 버전에서 웹 결제를 유도하거나 우회 결제처럼 보이는 흐름은 피한다.
- 제3자 미디어 저장/다운로드 기능은 명시적 허가, 저작권, 서비스 약관 문제가 확인된 경우에만 제공한다.

### 수익화와 기능 필터링

일부 기능은 구독형 또는 일회성 구매 풀버전 형태로 유료화할 수 있다. 가격, 상품명, 무료/유료 경계는 지금 확정하지 않는다. 먼저 제품 가치 기준으로 기능을 구현하고, 이후 정책/비용/사용자 반응을 보고 무료/유료/Pro 여부를 필터링한다.

후속 필터링 후보:

- 무료: 기본 영상 재생, 외부 자막 로딩, 제한된 AI 자막/번역 체험
- 유료: 긴 영상 자막 생성, 고정확도 모델, 한국어 번역 자막, 이중 자막, 배치 처리, 내보내기, 자막 관리
- Pro/Premium 후보: FFmpeg 고급 코덱, 브라우저 확장, DRM 없는 HLS 열기, 허용된 미디어 저장, 고급 로컬 모델 관리

구독형은 지속적인 모델 개선, 고급 AI 기능, 동기화, 대량 처리처럼 유지 비용이 있는 기능에 적합하다. 일회성 구매는 로컬 기능 잠금 해제, 고급 플레이어 기능, 자막 내보내기처럼 지속 서버 비용이 낮은 기능에 적합하다. 이 구분도 기능 완성 후 판단한다.
