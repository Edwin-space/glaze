# 재생 화면 — 탭, 스와이프 감도, 그리고 타임라인 스냅샷

작성일: 2026-09-22

## 1. 탭 한 번에 컨트롤이 사라지지 않았다

빈 화면을 탭하면 `revealControls()`가 불렸다. 컨트롤이 이미 떠 있어도 **다시 띄우고 타이머만
새로 시작**했으므로, 치우려고 탭한 바가 5초 더 남아 있었다.

탭은 어느 쪽이든 요청이다 — 보여달라, 혹은 비켜라. 규칙 자체는 `PlayerChromeIntent`로
공통 코드에 옮겨 테스트했다. 일시정지 중에는 그대로 둔다(자막을 읽거나 설정을 찾는 중에
버튼이 사라지면 두 번 탭해야 한다).

## 2. 밝기·음량 스와이프가 너무 민감했다

```swift
// 전
let level = UIScreen.main.brightness + delta * 0.06   // 지금 값에 더한다
```

`onChanged`는 손가락이 움직이는 동안 초당 수십 번 불린다. 그때마다 **직전에 자기가 올린
값에 또 더했으므로** 조금만 움직여도 끝까지 갔다. 손가락을 멈춰도 마지막 이동량이 계속
적용됐다.

이제 손가락이 **내려간 자리의 값**을 기준으로 이동 거리만큼만 바꾼다. 전체 범위를 움직이는
데 화면 세로의 대부분(600pt)이 필요하다. 음량도 같은 이유로 `SystemVolume.adjust(by:)`를
`set(_:)`로 바꿨다 — 단계가 아니라 위치다.

## 3. 타임라인 스냅샷

세 플랫폼 모두, 타임라인에서 가리키는 지점의 장면을 보여준다.

| 플랫폼 | 언제 | 어디에 |
|---|---|---|
| **아이폰·아이패드** | 타임라인을 끌거나 화면을 좌우로 스와이프하는 동안 | 바 바로 위, 가운데 고정 |
| **맥** | 포인터가 재생바 위에 있을 때, 그리고 끄는 동안 | 포인터가 가리키는 위치 |
| **애플TV** | 리모컨으로 타임라인을 움직이는 동안 | 바 위, 위치에 따라 이동 |

### 프레임을 어디서 얻는가

- **아이폰·애플TV** — VLCKit의 `VLCMediaThumbnailer`. 재생하는 엔진이 그대로 한 장을 뽑는다.
  MKV든 NAS 스트림이든 열 수 있는 유일한 수단이다(AVFoundation은 둘 다 못 연다).
  `Sources/GlazeShared`에 한 벌만 두고 두 타깃이 함께 컴파일한다
- **맥** — 번들된 ffmpeg. `-ss`를 입력보다 **앞에** 두어 키프레임으로 건너뛴다. 처음부터
  디코딩하면 포인터를 따라갈 수 없다

### 요청을 줄이는 부분이 핵심이다

드래그는 초당 수십 번 위치를 만들고, 한 프레임을 뽑는 데는 그보다 오래 걸린다. 공통
`ScrubPreviewLoader`가:

- 시간을 **5초 단위로 반올림**한다 — 손이 떨려도 같은 프레임을 두 번 묻지 않는다
- 이미 뽑은 프레임은 **기억**한다(60장, 320px JPEG이라 수 MB)
- 한 장을 만드는 동안 들어온 요청은 **가장 마지막 것만** 남기고 버린다. 줄 세우면 그림이
  손가락보다 몇 분 뒤처진다

## 4. 확인한 것

- 공통 로직 테스트 9개(반올림, 재사용, 중간 요청 버리기, 놓으면 지우기, 소스 없을 때 조용히,
  그리고 컨트롤 규칙 4개). 전체 362개 통과
- **맥**: 실제로 영화를 열고 재생바에 포인터를 올려 스냅샷과 시각 표시가 뜨는 것을 확인했다.
  처음에는 시각 표시 띠가 카드 밖으로 늘어나 있었고, 폭을 고정해 고쳤다
- **아이폰·애플TV**: 빌드와 공통 로직까지만 확인했다. 시뮬레이터의 합성 터치가 플레이어의
  탭 제스처에 닿지 않고(버튼에는 닿는다), 애플TV는 시뮬레이터에 리모컨 입력을 넣을 방법이
  없어 화면으로는 보지 못했다. **실기기 확인이 필요하다**

## 5. 남은 것

- 아이폰에서 탭 토글·스와이프 감도·스냅샷을 실기기로 확인
- 애플TV에서 리모컨으로 타임라인을 움직이며 스냅샷 확인
- 네트워크 영상의 스냅샷은 서버에서 그 지점을 다시 받아야 하므로 로컬 파일보다 느리다.
  느리면 5초 간격을 넓히거나 폭을 줄이는 쪽으로 조정할 수 있다
