# 서재와 즐겨찾기 — 아이폰·아이패드

작성일: 2026-09-07

## 왜 여기에만 넣는가

`docs/21`의 역할 분담에서 아이폰·아이패드는 "클라이언트"였다. 맥이 만든 것을 보는
자리. 이번에 하나가 더 붙는다 — **읽는 자리**.

만화와 PDF 책은 맥에서도 애플티비에서도 읽지 않는다. 손에 들고 넘기는 물건이고,
애플 기기 중 그런 물건은 아이폰과 아이패드뿐이다. 그래서 서재는 이 두 기기에만 있고,
`GlazeCore`에 든 해독기(zip·deflate·권 번호 파싱)는 세 플랫폼이 공유하되 화면은
여기서만 만든다.

## 이번에 만든 것

### 1. 서재 (탭 4개 중 하나)

보관함 / **서재** / 미디어 소스 / 설정.

| 선반 | 무엇이 오는가 |
|---|---|
| 읽는 중 | 펼쳤다가 끝내지 않은 책. 표지 아래에 진행 막대 |
| 즐겨찾기 | 별을 단 책과 시리즈 |
| 시리즈 | 같은 이름의 여러 권 — 표지 하나로 묶인다 |
| 단행본 | 권 번호가 없는 책 |

**권 번호를 파일 이름에서 읽는다.** `원피스 01권.cbz`부터 `원피스 24권.cbz`까지
스물네 개를 그대로 늘어놓으면 같은 책 표지가 스물네 장이다. 번호를 떼어내야 한 줄이
된다. `BookTitleParser`가 처리하는 형태:

- `원피스 01권` · `귀멸의 칼날 3화` · `슬램덩크 7집`
- `One Piece Vol. 3` · `v03` · `Volume 12` · `Berserk #14`
- `[스캔] 슬램덩크 07 (완전판)` — 대괄호 태그와 괄호 주석은 제목이 아니다
- `나루토 12` — 끝의 맨숫자는 **만화에서만** 권으로 읽는다.
  `Blade Runner 2049.pdf`를 2049권으로 만들지 않기 위해서다

한 권만 있으면 시리즈로 묶지 않는다. 안에 한 권뿐인 화면을 한 번 더 들어가게 만들
뿐이다.

### 2. 읽기

| | 만화 (`.cbz`) | 책 (`.pdf`) |
|---|---|---|
| 엔진 | `ComicArchive` + `UIPageViewController` | PDFKit |
| 넘기기 | 스와이프 | 스와이프 |
| 확대 | 두 손가락 · 두 번 탭 | PDFKit 기본 |
| 두 쪽 보기 | 가로로 눕히면 | 가로로 눕히면 |
| 읽기 방향 | 좌→우 / **우→좌(만화)** | 좌→우 / 우→좌 |

**읽기 방향은 책마다 따로 기억한다.** 앱 전체 설정 하나로 두면 만화와 PDF 매뉴얼을
오갈 때마다 사람이 바꿔야 한다. 설정의 값은 "새로 여는 책의 기본값"이고, 플레이어
안에서 바꾼 값은 그 책에만 붙는다. 기본값은 **우→왼쪽**이다 — 여기서 읽히는 것의
대부분이 한국·일본에서 그렇게 인쇄된다.

**표지가 첫 장이다.** 종이책의 표지는 혼자 인쇄된다. 두 쪽 보기에서 표지를 2쪽과
짝지으면 그 뒤의 모든 펼침이 한 장씩 어긋나고, 양면에 걸친 그림이 접힌 데서 끊긴다.
`ComicSpreads`가 이 규칙 하나만 담당하고, 테스트가 지킨다.

### 3. 즐겨찾기

폴더와 파일 어느 쪽이든 별을 달 수 있다.

| 무엇 | 별을 다는 곳 |
|---|---|
| 영화 | 보관함에서 포스터 길게 누르기 |
| 시리즈(폴더) | 보관함에서 포스터 길게 누르기 |
| 책 한 권 | 서재에서 표지 길게 누르기 |
| 시리즈 전권(폴더) | 서재에서 표지 길게 누르기 · 시리즈 화면 우상단 별 |

별을 단 것은 **보관함/서재 맨 위 선반**에 다시 나타난다. 원래 자리에서 사라지지는
않는다 — 즐겨찾기는 바로가기이지 이동이 아니다.

**저장하는 것은 참조뿐이다.** 라이브러리는 실행할 때마다 폴더를 다시 읽어서 만든다.
즐겨찾기가 항목을 통째로 들고 있으면 NAS에서 지운 영화가 별 아래에 영원히 남는다.
그래서 `sourceKey + kind + itemID`만 적어두고, 화면이 이번 스캔 결과와 맞춰본다.
없어진 것은 그냥 안 보인다.

라이브러리마다 별이 따로다(`sourceKey`). NAS의 영화와 전화기에 복사해둔 같은 영화는
다른 물건이고, 서버를 지워도 다른 서버의 별은 남는다.

## 세로 스크롤 (웹툰) — 2026-09-07 추가

읽기 방식이 세 가지가 됐다. **자동 판별이 아니라 사용자가 고른다.**

| | |
|---|---|
| 왼쪽 → 오른쪽 | 서양 책과 PDF |
| 오른쪽 → 왼쪽 | 만화 — 기본값 |
| **세로 스크롤** | **웹툰 — 끊김 없이 내린다** |

자동으로 알아내려면 이미지 비율을 보고 짐작해야 하는데, 한 권 읽는 도중에 틀리면
읽는 흐름이 깨진다. 한 번 묻는 편이 낫다. 책마다 따로 기억하고, 설정의 값은 새로 여는
책의 기본값이다.

만화(`.cbz`)는 `UICollectionView`로 이어 붙이고, PDF는 PDFKit의
`.singlePageContinuous`로 같은 일을 한다.

### 웹툰 한 장은 페이지가 아니다

세로로 긴 리본을 페이지처럼 화면에 맞추면 읽을 수 없는 조각이 된다. 두 가지가 필요했다.

1. **폭 기준으로 줄인다.** 페이지 모드는 긴 변을 2600px로 자르지만, 800×10000 리본을
   그렇게 자르면 208px 폭이 된다. 세로 모드는 폭을 1400px로, 총 화소를 600만으로 자른다
2. **모든 쪽의 높이를 미리 안다.** 이어 붙이려면 배치 전에 각 쪽의 비율을 알아야 한다.
   `ComicArchive.pageSize(at:)`가 이미지 헤더만 읽는다 — 부분 압축 해제를 넣어
   한 쪽당 수십 KB만 펴면 되므로, 400쪽짜리도 볼륨 전체를 펴지 않는다

## 만들면서 고친 것

### 파일 경로를 식별자로 쓰면 안 됐다

앱의 Documents 폴더는 iOS가 정하는 컨테이너 id 아래에 있고, 그 id는 바뀔 수 있다.
절대 경로를 식별자로 쓰면 그 id가 **기억한 페이지와 즐겨찾기 전부에** 들어간다.
실제로 재설치하고 나니 읽던 책이 사라졌다.

`LocalLibraryLoader.identifier(for:root:)`가 스캔 시작 폴더 기준의 상대 경로를
돌려준다. `테스트만화 01권.cbz`. 영화도 같이 바꿨다.

### 한글 파일 이름은 자모로 분해되어 온다

맥의 파일 시스템은 한글을 분해형(NFD)으로 돌려준다. `권`이 세 개의 코드 포인트로
오기 때문에, 정규식에 적어둔 `권`과 맞지 않는다. **한국어 만화의 권 번호가 하나도
안 잡혔다.** `BookTitleParser`가 이름을 먼저 `precomposedStringWithCanonicalMapping`
으로 합친다.

### 책을 덮어도 선반이 몰랐다

`ReadingPositionStore`는 `UserDefaults`를 읽고 쓰는 구조체다. 아무도 그걸 지켜보지
않는다. 3쪽에서 덮으면 값은 저장되는데 서재의 진행 막대는 그대로였다 — 화면이 어쩌다
다시 만들어질 때까지.

`ReadingProgressStore`(`@Observable`)를 두어 같은 값을 메모리에도 들고 있게 했다.
선반은 이쪽을 읽는다.

### 리더 안에서는 아무것도 띄울 수 없었다

읽기 방향을 고르는 자리를 `Menu`로 만들었더니 열렸다가 0.1초 만에 스스로 닫혔다.
`sheet`으로 바꿔도 같았다. 로그를 찍어 보니 원인은 단추가 아니었다 — **무언가를 띄우는
순간 리더 뷰 자체가 화면에서 빠졌다 다시 들어오고, `@State`가 초기화된다.**
`task`가 다시 돌면서 아카이브를 처음부터 다시 열고, 그 아래에서 페이지 저장소가
새로 만들어지면서 띄운 것을 함께 데려갔다.

`fullScreenCover` 안에서 다시 무언가를 띄우는 구조의 문제로 보이나, 정확한 원인은
찾지 못했다. **띄우지 않는 쪽으로 바꿨다** — 읽기 방향은 하단 바에 세그먼트 컨트롤로
그냥 놓여 있다. 없앨 것이 없으면 없어지지도 않는다. 결과적으로 더 나은 자리이기도 하다:
바꾸면서 그 결과를 바로 보는 물건이다.

### 표지를 매번 다시 풀지 않는다

만화 표지는 zip을 열어 첫 장을 꺼내야 나오고, PDF 표지는 문서를 열어야 나온다.
마흔 권짜리 서재가 실행할 때마다 마흔 번 그 짓을 한다. 캐시 폴더에 그려둔 것을
쓰고, 키에 파일 크기를 섞는다 — 같은 이름으로 더 좋은 스캔을 덮어썼을 때 옛 표지가
남지 않도록.

## 왜 `.cbr`은 없는가

RAR 압축이고, 쓸 수 있는 해독기의 라이선스가 이 저장소에 맞지 않는다.
**지원하지 않기로 정했다** — 판단과 근거는 `docs/33`.

## 확인한 것

아이폰 17 Pro 시뮬레이터, 실제 파일(생성한 `.cbz` 3권 + 실제 PDF)로:

- 서재 탭에 시리즈(전 3권)와 단행본이 나온다. 표지는 각각 zip 첫 장과 PDF 1쪽
- 만화 열기 → 1/12 표시, 슬라이더, 오른쪽→왼쪽 스와이프로 2/12
- 하단 바의 읽기 방향 세그먼트(좌→우 / 우→좌 / 세로)로 모드가 그 자리에서 바뀐다
- 웹툰 `.cbz`(700×3000 리본 8장)를 세로 모드로 열면 화면 폭에 맞춰 이어지고,
  내리면 1/8 → 3/8으로 쪽 표시와 슬라이더가 따라온다. 페이지 모드에서는 같은 파일이
  읽을 수 없는 세로 조각이 된다 — 모드가 하는 일이 그것이다
- PDF 열기 → PDFKit 렌더링
- 표지 길게 누르기 → 즐겨찾기에 추가 → 맨 위에 즐겨찾기 선반 생성, 별 배지
- 책을 덮으면 읽는 중 선반과 진행 막대가 **바로** 갱신된다

아이패드 프로 13" 시뮬레이터(`simctl io screenshot`으로 확인):

- 탭바는 상단에 한 번만 (docs/25의 "중복" 기록은 캡처 도구 문제였다 — 정정함)
- 시리즈 화면, 권 목록, 리더 모두 정상
- 두 쪽 펼침: 표지는 혼자, 그다음이 2·3쪽 나란히. 우→좌라 낮은 쪽 번호가 오른쪽

## 확인하지 않은 것

- **아이패드를 실제로 눕혀서 본 두 쪽 보기.** 시뮬레이터 회전이 되지 않아,
  조건(`가로 && 설정 켜짐`) 대신 강제로 켜서 배치만 확인했다. 짝짓기 규칙은
  `ComicSpreadsTests`가 지킨다
- **실기기.** 아이폰 16 Pro와 애플TV에 빌드 1.0(7)을 넣었지만 그것은 웹툰 모드 이전
  빌드다. 웹툰 모드가 든 빌드는 아직 실기기에 올리지 못했다 (설치 시점에 아이폰이
  네트워크에서 빠져 있었다). 아이패드는 이 맥에 페어링되어 있지 않다
- **큰 파일.** 300쪽짜리 스캔본, 500MB PDF에서의 메모리와 첫 화면까지의 시간.
  페이지는 2600px로 줄여 디코드하고 다섯 장만 들고 있지만, 실측은 아직이다
- **NAS의 책.** 서재는 기기 안의 폴더만 읽는다. NAS에 있는 만화를 바로 여는 것은
  파일 전체를 받아야 하는 일이라 이번 범위에 넣지 않았다
- **세로 모드의 확대.** 웹툰은 폭에 맞춰 놓이므로 확대할 일이 적다고 보고 넣지 않았다.
  세로 모드로 스캔본을 보는 사람에게는 아쉬울 수 있다
- **긴 볼륨의 첫 진입.** 400쪽짜리를 세로 모드로 처음 열면 쪽 크기를 재는 시간이 있다.
  헤더만 읽으므로 빨라야 하지만 실측하지 않았다
