# 글레이즈 기본 제품/개발 계획

작성일: 2026-06-18  
프로젝트명: 글레이즈

## 문서 목적

이 문서는 글레이즈를 실제 개발 단계로 진입시키기 위한 기본 계획서다. 앞서 정리한 Mac App Store 벤치마크, 제품 방향, AI 자막 생성 워크플로우를 하나의 실행 기준으로 묶고, 기능 범위, 디자인 방향, 기술 방향, MVP 개발 순서를 정의한다.

## 제품 판단

글레이즈는 범용 영상 플레이어 시장에서 Infuse, VidHub, Plex, MX Video Player HD 같은 제품과 직접 경쟁한다. 다만 초기 전략은 "가장 많은 코덱을 지원하는 플레이어"가 아니라 "자막 없는 영상과 정리되지 않은 개인 영상 라이브러리를 감상 가능한 상태로 준비해주는 AI 미디어 라이브러리 플레이어"가 되어야 한다.

핵심 포지션은 다음과 같다.

> Apple Silicon 온디바이스 AI로 개인 영상 라이브러리를 자막화, 번역, 메타데이터 정리까지 준비해주는 macOS AI 미디어 플레이어.

## 벤치마크 기반 경쟁 구도

### Infuse

Infuse는 Apple 생태계형 미디어 라이브러리 플레이어의 기준점이다. 로컬 파일, NAS, Plex, Emby, Jellyfin, 클라우드 연동, 메타데이터, 자막 다운로드, Apple TV 연동이 강하다.

글레이즈가 배워야 할 점은 라이브러리 정리, 기기 간 경험, 포스터/메타데이터 기반 탐색이다. 정면으로 피해야 할 영역은 초기부터 모든 미디어 서버와 모든 코덱을 완성도 높게 지원하려는 접근이다.

### Plex

Plex는 개인 NAS/서버 기반 미디어 경험의 강력한 기준점이다. 사용자는 로컬 파일을 폴더에 넣고, 서버가 작품 정보를 매칭하고, Apple TV/iPhone/iPad 같은 기기에서 이어볼 수 있다.

글레이즈가 배워야 할 점은 미디어 서버, 포스터/메타데이터, 시청 위치 동기화, 거실 감상 연속성이다. 다만 글레이즈는 Plex와 정면으로 서버 플랫폼 경쟁을 시작하기보다, macOS에서 자막/번역/메타데이터 준비를 자동화하고 이후 NAS/Apple TV로 확장하는 순서가 맞다.

### VidHub

VidHub는 Infuse 대안에 가까운 라이브러리 플레이어다. SMB, WebDAV, 클라우드, 미디어 서버 연동과 iCloud 동기화가 강점이다.

글레이즈가 참고할 점은 "개인 영상 보관함" 중심의 정보 구조다. 다만 VidHub도 자막이 없는 영상을 자동으로 이해하고 한국어 시청 준비를 해주는 경험은 핵심이 아니다.

### MX Video Player HD

MX Video Player HD는 리뷰 수와 대중성 측면에서 의미가 있지만, 고급 macOS 네이티브 플레이어의 신뢰감이나 AI 기반 차별성은 약하다.

글레이즈는 단순 포맷 지원 앱처럼 보이면 안 된다. 제품 메시지, 설정 구조, 상태 표시, 자막 생성 경험에서 더 전문적인 인상을 줘야 한다.

### 추가 관찰 대상

Elmedia, MKPlayer, OmniPlayer, Movist는 기능 벤치마크 대상으로 계속 관찰한다. 특히 Movist는 한국 사용자 관점에서 자막 품질, 디코더 선택, 세밀한 플레이어 설정을 참고할 가치가 있다.

### Submarine Player

Submarine Player는 글레이즈가 가장 중요하게 봐야 할 직접 레퍼런스다. Apple Silicon 및 macOS 15 이상을 요구하며, 영상 재생 중 실시간 AI 자막 생성과 번역, 오프라인 처리, 19개 언어 지원, 원문/번역 이중 자막, SRT/VTT/CSV 내보내기, 배치 처리를 핵심 기능으로 제공한다.

이 제품은 글레이즈의 문제 정의가 시장적으로 유효하다는 근거다. 동시에 "AI 자막 생성"만으로는 차별화가 부족하다는 신호이기도 하다. 글레이즈는 Submarine Player의 실시간 자막 생성 경험을 참고하되, 한국어 중심의 사전 자막 준비, 라이브러리 단위 자동화, 생성 후 편집/검수/재사용 경험에서 더 깊어져야 한다.

추가 차별화 후보로 브라우저 확장 연동을 둔다. Submarine Player가 로컬 파일 기반 AI 자막 플레이어에 가깝다면, 글레이즈는 Chrome/Safari 확장을 통해 사용자가 웹에서 보던 DRM 없는 영상을 글레이즈로 열고, 자체 플레이어에서 자막 생성/번역/저장을 이어가는 방향을 실험할 수 있다.

## 차별화 원칙

- 기존 플레이어는 "있는 자막을 잘 붙이는" 쪽에 강하다.
- 글레이즈는 "없는 자막을 만들어 재사용 가능한 자산으로 남기는" 쪽에 집중한다.
- AI 기능은 전면 장식이 아니라 감상 준비를 자동화하는 기반 기능이어야 한다.
- 한국어 번역 자막은 부가 기능이 아니라 기본 경험에 가깝게 설계한다.
- 재생 중 실시간 처리보다 재생 전 사전 생성과 백그라운드 큐를 우선한다.
- Submarine Player가 이미 보여준 실시간 AI 자막 경험을 전제로, 글레이즈는 라이브러리 준비형 AI 플레이어로 포지셔닝한다.
- Plex/Infuse가 보여준 메타데이터와 기기 연속성을 전제로, 글레이즈는 AI 자막/번역/파일 정리까지 포함한 개인 미디어 준비 경험으로 확장한다.
- 브라우저 확장 연동은 보호 콘텐츠 우회 도구가 아니라, 정당하게 접근 가능한 웹 영상을 글레이즈 감상 환경으로 가져오는 브릿지로 설계한다.

## 목표 사용자

- 외국어 영상을 자주 보는 한국 사용자
- 자막이 없는 강의, 인터뷰, 세미나, 영화, 드라마를 보는 사용자
- NAS, 외장 디스크, 로컬 폴더에 개인 영상 라이브러리를 보관하는 사용자
- 개인정보 보호와 로컬 처리를 선호하는 사용자
- 외국어 학습 목적으로 원문/한국어 이중 자막을 활용하려는 사용자

## MVP 기능 범위

MVP는 "영상 재생 + 단일 영상 수동 AI 자막 생성 + 저장 + 자동 연결 + 한국어 번역"까지를 목표로 한다.

## 플랫폼 확장 로드맵

글레이즈는 초기부터 글로벌 제품을 지향하지만, 모든 플랫폼을 동시에 지원하지 않는다. 우선 macOS Apple Silicon에서 핵심 가치를 증명하고, 이후 모바일과 Windows로 순차 확장한다.

### 1단계. macOS Apple Silicon

초기 주력 플랫폼이다. AI 자막 생성, 한국어 번역, 자막 저장, 라이브러리 준비, 배치 처리, 브라우저 확장 실험까지 가장 적합한 환경이다.

### 2단계. iOS/iPadOS

macOS MVP가 안정화된 뒤 보조 감상 앱으로 확장한다. 모바일에서는 긴 영상 자막 생성보다 macOS에서 준비된 자막과 라이브러리를 이어서 보는 경험을 먼저 제공한다.

### 3단계. Android

글로벌 모바일 확장 후보로 둔다. 기기 성능 편차와 AI 모델 최적화 난이도가 크므로 iOS/iPadOS 이후 검토한다.

### 4단계. Windows

글로벌 데스크톱 확장 후보로 둔다. 시장 규모는 크지만 하드웨어, 코덱, GPU 환경 편차가 크므로 macOS에서 제품 가치가 검증된 뒤 진입한다.

초기 UI 기본 언어는 한국어와 영어다. 이후 중요 국가 언어는 기계 번역 초안과 사람 검수를 조합해 확장하되, 결제, 개인정보, 다운로드, DRM 관련 문구는 반드시 검수한다.

## 핵심 화면 설계 방향

### 플레이어 화면

플레이어 화면은 영상 감상이 중심이다. AI 기능은 필요할 때만 나타나야 하며, 기본 화면을 복잡하게 만들면 안 된다.

필수 요소는 다음과 같다.

- 영상 영역
- 재생 컨트롤
- 탐색바
- 자막 토글
- 자막 언어 선택
- 자막 생성 상태
- 전체화면과 PIP

### 자막 생성 패널

자막 생성 패널은 사용자가 현재 작업을 이해하고 제어할 수 있어야 한다.

- 현재 상태: 대기, 오디오 추출, 음성 인식, 정리, 번역, 완료, 실패
- 진행률
- 예상 남은 시간
- 모델 모드: 빠른 모드, 표준 모드, 고정확도 모드
- 출력: 원어 자막, 한국어 번역, 이중 자막
- 저장 위치: 앱 내부, 영상 옆 파일
- 작업 제어: 시작, 일시정지, 취소, 다시 시도

### 라이브러리 화면

MVP 이후 라이브러리 화면은 "무엇을 볼 수 있는가"보다 "무엇이 감상 준비됐는가"를 보여줘야 한다.

- 영상 목록
- 포스터/작품 정보 매칭 상태
- 자막 상태
- 번역 상태
- 마지막 재생 위치
- 파일 위치
- 보관 위치: 로컬, NAS, iCloud, 서버
- 작업 큐 상태
- 실패 사유

### AI 미디어 어시스턴트

AI 미디어 어시스턴트는 챗봇처럼 사용자를 방해하는 대화창이 아니라, 현재 영상 또는 라이브러리 항목에 대해 다음 준비 행동을 제안하는 작은 에이전트다.

- 파일명 기반 작품 후보 찾기
- 자막 없음 감지
- 한국어 번역 자막 생성 제안
- 포스터/줄거리/시즌 정보 매칭 후보 표시
- sidecar metadata 저장 제안
- 원본 파일 태그 쓰기는 사용자가 명시적으로 선택할 때만 제공

### 브라우저 확장 화면

MVP 이후 선택 기능으로 검토한다. 확장은 현재 페이지에서 감지한 동영상을 보여주고, 사용자가 명시적으로 선택한 항목만 글레이즈 앱으로 전달한다.

- 현재 페이지의 재생 가능한 미디어 감지
- HLS `.m3u8`, DASH `.mpd`, 직접 파일 URL 표시
- "글레이즈에서 열기" 액션
- DRM 또는 보호 콘텐츠 감지 시 비활성화
- 다운로드는 허용된 미디어에 한해 별도 액션으로 분리

## 디자인 원칙

- macOS 네이티브 감각을 우선한다.
- 영상 영역은 조용하고 어둡게, 설정과 라이브러리는 밝고 정보 중심으로 설계한다.
- 버튼과 상태 문구는 한국어 사용자가 즉시 이해할 수 있게 쓴다.
- AI 용어보다 사용자 결과를 먼저 보여준다.
- 상태 표시는 숨기지 않는다. 특히 실패와 권한 문제는 명확해야 한다.
- 고급 설정은 깊게 두고, 기본값만으로도 바로 쓸 수 있게 한다.

## 기술 방향

### 앱 구조

- SwiftUI: 앱 UI와 설정 화면
- AVFoundation/AVKit: 기본 재생
- FFmpeg 검토: MKV, 특수 코덱, 오디오 추출 보완
- Core Data 또는 SQLite: 라이브러리, 자막 인덱스, 작업 큐 저장
- MediaAsset 모델: 파일 위치, 보관 소스, 메타데이터, 자막 준비 상태, 시청 위치를 분리 관리
- Metadata Provider: IMDb/TMDB/TVDB 등 외부 공급자를 추상화하고 라이선스/상업 사용/attribution을 공급자별로 관리
- Core ML/Metal: 온디바이스 음성 인식 모델 실행 검토
- SRT/VTT: 초기 자막 저장 포맷

### 주요 모듈

- Player Core: 재생, 탐색, 오디오/자막 트랙 제어
- Subtitle Engine: 외부 자막 로딩, 생성 자막 연결, 표시
- AI Subtitle Engine: 오디오 추출, 음성 인식, 타임스탬프 정리
- Translation Engine: 한국어 번역, 번역 캐시
- Job Queue: 자막 생성 작업 상태와 재시도
- Resource Scheduler: 배터리, 전원, 발열, 시스템 부하 정책
- Library Manager: 영상 목록, 파일 위치, 자막 상태 관리
- Metadata Manager: 작품 매칭, 외부 ID, 포스터/줄거리, sidecar metadata 관리
- Sync Layer: iCloud 또는 계정 기반 시청 위치/자막 상태 동기화 후보

## 개발 단계

### Phase 0. 프로젝트 기반 정리

- Git 저장소 초기화
- Swift/macOS 프로젝트 생성
- 문서와 개발 소스 구조 분리
- 기본 빌드, 실행, 테스트 명령 정의

### Phase 1. 플레이어 MVP

- 로컬 영상 파일 열기
- 기본 재생 컨트롤
- 탐색바와 전체화면
- 외부 SRT/VTT 자막 로딩
- 최근 파일 목록

### Phase 2. 수동 자막 생성 MVP

- 영상에서 오디오 추출
- 샘플 음성 인식 파이프라인 연결
- 원어 자막 생성
- SRT 저장
- 생성 자막 자동 연결
- 진행률 표시

### Phase 3. 한국어 번역 자막

- 원어 자막 문장 단위 번역
- 한국어 SRT 저장
- 원문/한국어/이중 자막 표시
- 번역 실패 처리

### Phase 4. 자막 준비 큐

- 재생목록 추가 시 자막 존재 여부 확인
- 자막 없는 영상 작업 큐 등록
- 작업 상태 저장
- 앱 재실행 후 작업 상태 복구
- 일시정지, 재개, 재시도

### Phase 5. 라이브러리와 자동화

- 폴더 등록
- 라이브러리 목록
- 자막/번역 상태 표시
- 전원 연결 시 자동 처리
- 배터리 사용 중 자동 일시정지

## 초기 의사결정 필요 사항

- MVP는 Apple Silicon 전용으로 시작한다.
- 최소 지원 버전은 macOS 15로 둔다.
- 초기 UI 언어는 한국어/영어이며, 시스템 언어 자동 감지 후 미지원 언어는 영어로 fallback한다.
- 초기 영상 재생은 AVFoundation/AVKit으로 시작한다.
- FFmpeg는 MVP 시작 시점에는 붙이지 않지만, 고해상도 MKV 수요 때문에 Player MVP 직후 빠른 도입 검증 대상으로 둔다.
- 음성 인식 모델 후보와 라이선스
- 한국어 번역은 온디바이스 우선이며, 온라인 번역은 후순위 선택 옵션으로 둔다.
- 자막 저장 위치는 사용 흐름별로 사용자에게 묻는다.
- 생성 자막 편집 기능을 MVP에 포함할지, 1차 이후로 둘지
- SRT/VTT/CSV 내보내기를 MVP에 포함할지
- 브라우저 확장 연동을 어느 Phase에서 실험할지
- HLS 감지와 재생까지만 할지, 허용된 미디어 저장까지 제공할지
- DRM/EME 감지와 차단 정책을 어떻게 사용자에게 설명할지
- iOS/iPadOS를 보조 감상 앱으로 둘지, 독립 생성 앱으로 키울지
- Windows 진입 시 AI 엔진을 어떤 런타임으로 이식할지
- 글로벌 영문명을 `Glaze`로 확정할지
- App Store 배포를 목표로 하되, 웹 배포/프리미엄 제품군과 기능 차이를 어떻게 둘지
