# 애플TV — DLNA가 WebDAV 없이는 동작하지 않던 이유

작성일: 2026-09-19

증상: 애플TV에서 **DLNA만 설정하면 아무것도 불러오지 못하고**, WebDAV를 함께 설정해야
데이터가 보인다.

## 1. 원인 — 검색 신호를 보낼 수 없다

DLNA 검색(SSDP)은 `239.255.255.250:1900`으로 보내는 **멀티캐스트**다. iOS 14부터 멀티캐스트
전송에는 `com.apple.developer.networking.multicast` 엔타이틀먼트가 필요하고, 이는 애플에
신청해 승인받아야 한다. **tvOS도 똑같다.**

`docs/34`에 이 내용이 iOS 기준으로만 적혀 있었고, 애플TV에는 아무 대응도 하지 않은 채
남아 있었다. 그래서 실기기에서는:

- 검색이 **아무 서버도 찾지 못한다** (시뮬레이터는 이 제한을 강제하지 않아 잘 된다)
- 소스 화면은 "서버를 찾지 못했습니다"만 보여준다 — NAS가 멀쩡히 돌고 있는데도
- WebDAV는 주소를 직접 입력하므로 멀쩡히 동작한다 → "WebDAV가 있어야만 된다"로 보인다

검색 이후의 코드는 멀쩡했다. 테스트용 DLNA 서버를 세워 확인한 결과, 서버를 **알기만 하면**
설명 파일 읽기 → ContentDirectory Browse → 폴더/영상 목록 → 재생 주소까지 모두 정상이다
(`UPnPServerLocatorTests`, `DLNAFolderReadingTests`).

## 2. 고친 것

### 주소로 서버를 직접 찾는 길 (`UPnPServerLocator`)

멀티캐스트 없이 서버 하나에게만 묻는다. 순서대로:

1. **유니캐스트 SSDP** — 입력한 주소의 1900 포트로 M-SEARCH를 보낸다. 대부분의 서버가
   브로드캐스트와 똑같이 답하고, 답에는 설명 파일의 실제 주소가 들어 있다. 유니캐스트 UDP는
   엔타이틀먼트가 필요 없다
2. **알려진 주소** — 답이 없으면 8200(minidlna·시놀로지 미디어 서버), 9000(Twonky),
   32469(Plex), 8096(Jellyfin) 등에서 설명 파일을 찾는다
3. 설명 파일 주소(`rootDesc.xml`)를 그대로 붙여 넣은 경우는 그것을 그대로 쓴다

호스트 이름도 받는다(`getaddrinfo`로 해석). IP만 적어도, 포트를 적어도, 전체 주소를 적어도
같은 곳에 도착한다.

### 입력한 서버는 남는다 (`SavedMediaServerStore`)

검색이 동작하지 않는 기기에서 주소를 매번 다시 입력하게 하면 쓸 수 없는 기능이다. 설명 파일
주소만 저장하고, **켤 때마다 다시 읽어** 서버를 만든다 — NAS가 재시작하면 제어 주소가
바뀌는데, 몇 주 전에 받아둔 값을 믿으면 재생하려는 순간에 실패한다.

검색을 다시 돌려도 입력해 둔 서버는 목록에서 사라지지 않는다.

### 애플TV 화면

- 소스 → 자동 발견에 **주소로 추가** 버튼
- 서버가 없을 때의 안내가 "찾지 못했습니다"에서 **"애플TV는 네트워크 전체에 검색 신호를 보낼
  수 없습니다. 주소를 직접 입력하면 바로 연결됩니다"** 로 바뀌었다. 검색 자체가 실패한
  경우에는 그 오류를 그대로 보여준다

### 고른 소스가 무시되던 것 — 두 번째 버그

시작할 때 여는 소스를 고르는 `loadPreferredSource`가 **WebDAV NAS가 하나라도 저장되어 있으면
거기서 끝났다.** 소스 화면에서 DLNA 서버를 직접 골라도, 앱을 다시 켜면 WebDAV가 열리고
DLNA는 없는 것이 되었다. 애플TV 시뮬레이터에서 추적해 확인했다(`webdav=1`에서 멈춘다).

이제 **마지막에 고른 것이 이긴다**: 골라둔 미디어 서버가 있으면 그것을 열고, NAS를 새로
고르면 그때 미디어 서버 선택이 풀린다.

### WebDAV가 있으면 DLNA를 무시하던 것

`adoptDLNAIfNeeded`에 `connections.connections.isEmpty` 조건이 있었다. WebDAV NAS가 하나라도
저장되어 있으면, 소스 화면에서 **직접 고른** DLNA 서버조차 보관함으로 열리지 않았다.
조건을 없앴다 — 고른 것은 고른 것이다.

또 저장된 서버는 검색 없이 먼저 복원되므로, 앱을 켜면 곧바로 지난번 서버가 준비된다.

## 3. 확인한 것

테스트용 DLNA 서버(SSDP 응답 + 설명 파일 + ContentDirectory Browse)를 세워서:

- 설명 파일 주소로 찾기 / IP+포트로 찾기 / **유니캐스트 SSDP로 찾기**
- 찾은 서버를 Browse 해서 폴더 → 영상 → 재생 주소까지 읽기
- 아무도 없는 주소는 빈 목록이 아니라 **실패로** 보고하기

그리고 **애플TV 시뮬레이터에서 화면으로 확인했다.** 기기를 완전히 지운 뒤:

1. 주소로 추가한 DLNA 서버의 폴더가 **WebDAV 없이** 폴더 탭에 나온다
2. 앱을 껐다 켜면 그 서버가 그대로 복원되고, **홈 선반에 영상이 올라온다**
   (`Testmedia · Test DLNA Server의 영상 보관함`)
3. 미디어 소스 화면에 `주소로 추가` 버튼이 있고, 발견된 서버 목록도 함께 보인다

시뮬레이터는 멀티캐스트 제한을 받지 않으므로 자동 발견도 함께 동작한다. 실기기에서
동작하지 않는 것은 그 제한 때문이라는 점이 이것으로 다시 확인된다.

## 4. 남은 것

- **멀티캐스트 엔타이틀먼트 신청**(계정 소유자). 승인되면 자동 검색이 실기기에서도 동작하고,
  주소 입력은 그때도 백업 경로로 남는다
- 아이폰·아이패드에도 같은 제한이 있다. 공통 코드는 이미 들어갔으므로 화면만 붙이면 된다
- 실제 시놀로지 미디어 서버로 애플TV에서 확인 (사용자)
