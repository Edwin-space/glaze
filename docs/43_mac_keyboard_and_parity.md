# 맥 — 키보드 단축키, 그리고 세 플랫폼 같은 재생 경험 (2026-09-15)

## 무엇이 없었나

맥 플레이어가 받는 키는 **스페이스 하나**였다. 방향키로 건너뛰기도, 소리 조정도, 다음 영상
단축키도 없었다. 재생 목록은 `Gundam.0083.E01.mkv` 같은 파일 이름 그대로였고, 본 것 표시도,
키보드의 ⏮⏯⏭ 키도 없었다.

## 1. 단축키 — 기본값과 설정

| 동작 | 기본 키 |
|---|---|
| 재생 / 일시정지 | Space |
| 10초 뒤로 / 앞으로 | ← / → |
| 소리 크게 / 작게 | ↑ / ↓ (5%씩) |
| 이전 / 다음 영상 | ⌘← / ⌘→ |

영상 이동은 **조합 키**다. 방향키만 스치고 다음 화로 넘어가 버리면 안 되므로.

**설정 › 키보드**에서 전부 바꿀 수 있다. 버튼을 누르고 새 키를 누르면 된다. ⎋는 취소, ⓧ는
지우기, **기본값으로 되돌리기**.

- 이미 다른 동작이 쓰는 키를 지정하면 **그 동작에서 빼고** 옮긴다. 둘이 한 키에 겹쳐 동시에
  실행되지 않는다. 옮겼다는 사실은 화면에 한 줄로 알린다
- **지운 단축키는 다시 실행해도 지워진 채로 남는다.** 처음 구현에서는 저장할 때 지운 키가
  빠져서, 다음 실행에 기본값이 되살아났다. 저장 시점에 있던 동작 목록을 함께 적어 "일부러
  지운 것"과 "나중 버전에 새로 생긴 동작"을 구분한다

### 키 코드로 저장하는 이유

- 방향키에는 **글자가 없다**
- 한글 입력기에서는 같은 키가 **다른 글자**가 된다. 글자로 저장하면 한글로 바꾸는 순간 단축키가
  멈춘다
- 맥은 방향키에 **fn·키패드 플래그**를 붙여 보낸다. 이걸 거르지 않으면 방향키 단축키가 아예
  맞지 않는다 — 모델 검증에서 잡았다

### 가로채지 않는 경우

- **글자를 입력하는 칸**(TMDB 검색, 자막 싱크)에서는 방향키가 커서를 움직인다
- **설정 창과 시트**에서는 동작하지 않는다
- 설정에서 **키를 녹화하는 동안**에는 플레이어가 그 키에 반응하지 않는다. → 를 지정하려고
  누른 순간 영상이 10초 넘어가면 안 되므로

## 2. 폰·TV와 같은 재생 경험

- **재생 목록**: 화수 먼저(`E01 · Gundam 0083`), NEW / 진행 막대 / 다 봄, 우클릭으로 표시 바꾸기
- **이전 영상**: 5초 이후엔 처음으로, 처음 몇 초에만 앞 편. 맥은 40분 지점에서도 앞 파일로 튀었다
- **매체 키**: 키보드의 ⏮⏯⏭, 제어 센터, 에어팟. 전에는 영화를 보는 중에 ⏯를 누르면 **음악 앱이
  재생됐다**

## 3. 덤 — 재생 목록 순서가 틀려 있었다

`E02`를 열면 목록이 **E02, E01, E03, E04**였다. 목록 생성기가 일부러 연 파일을 맨 위로 올리고
있었다. 그래서 E02에서 "다음"이 **E01**로 갔고, E02에는 "이전"이 없었다. 요청하신 이전/다음을
정면으로 망가뜨리는 기존 결함이다.

폴더 순서를 그대로 쓰고, 플레이어는 목록에서 현재 영상을 찾아 위치를 정한다. 회귀 테스트로
묶었다(E10이 E9 뒤에 오는 것까지).

## 확인한 것 — 실행 중인 맥 앱에 실제 키 입력으로

```
재생 목록        E01 NEW / ▶ E02 / E03 NEW / E04 NEW   (폴더 순서)
⌘→              제목이 E03으로, E02는 NEW → 진행 막대
일시정지 0:36 → → → 0:56 → ← 0:46 → ↓↓↓ 0:46 (시간 그대로, 소리 100%→약 85%)
설정 › 키보드    기본값 일곱 줄 표시
"10초 앞으로" → L 녹화         L로 표시
"10초 뒤로" → ↑ 녹화          ↑로, "소리 크게"는 "없음"
플레이어에서     →(미지정) 0:09 그대로, L 0:19
```

단축키 모델은 따로 떼어 10가지를 검증했다(기본값, 충돌 이동, 지운 키 유지, 되돌리기, fn
플래그 무시).

첫 녹화 시도에서 L 대신 S, ↑ 대신 R이 기록된 적이 있다. 진단 로그를 넣고 같은 절차를 두 번
다시 돌렸을 때는 모두 정확했고 유령 키도 없었다. 그 직전에 멈춰 있던 접근성 스크립트와 겹친
것으로 보지만 **원인을 증명하지는 못했다.** 진단 로그는 제거했다.

테스트용으로 바꾼 단축키는 **기본값으로 되돌려 두었다**(`defaults delete`가 적용되지 않아 기본값을
직접 써넣고 읽어서 확인).

## 확인하지 않은 것

- **키보드의 ⏮⏯⏭ 매체 키** — 코드는 붙였지만 물리 키로 눌러보지 않았다
