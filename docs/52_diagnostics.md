# 기기 내 진단 — 2026-11-09

기록은 기본 꺼짐. iPhone 설정 → 정보 → 진단에서 켠 뒤 테스트한다. 앱 강제 종료 후에도
최근 기록은 남는다. 재실행 → 진단 파일 준비 → 진단 파일 공유에서 AirDrop/파일로 내보낸다.
마켓 빌드에서도 같은 명시적 opt-in을 사용한다. 자동 업로드는 없다.

공통 DiagnosticsCenter가 직렬 utility 큐로 JSONL을 쓴다. OSLog에는 고정 이벤트 이름만
남긴다. 파일 5MB × 3개, 7일 보존, 백업 제외. 진단 화면에서 삭제할 수 있다.
내보내기는 파일을 오래된 순서로 합치고 앱/OS 버전을 붙인다.

원문 오류, 파일/폴더명, 서버 주소, 자막/번역 본문, 인증 값은 기록하지 않는다.
이벤트는 StaticString, 값은 숫자, 자료 식별은 설치별 HMAC으로 제한한다.
시스템 uptime은 내보내지 않고 앱 실행 후 경과 시간과 작업 간 소요 시간만 쓴다.
PrivacyInfo의 CA92.1/C617.1/35F9.1과 사이트 정책을 함께 유지한다.

계측: 앱 시작/활성 상태/메모리 경고, 공통 폴더 읽기, WebDAV 목록, Synology 요청,
DLNA Browse, 자막 다운로드, 미리보기, iPhone 재생·seek·stop·상태·버퍼,
도서 보관함 갱신, 탭 이동, Mac 재생/자막 생성/번역, TV 재생 시작/종료.

같은 UUID의 operation.end를 연결한다. end가 없으면 작업 중 종료/대기를 의심하고,
success=0이면 throw 또는 취소 경로를 확인한다. 각 iPhone 재생은 UUID로 구분하고 이전
재생의 지연 콜백은 배제한다. 메인 큐 heartbeat 10초 지연, 재생 시간 15초 정체 시
별도 큐에서 이벤트를 남긴다. 일시정지/비활성화와 함께 해석한다. 이벤트는 의심 징후이며
무한 루프의 증명이 아니다. C 라이브러리 교착 스택은 Xcode/기기 진단으로 보완한다.

iOS MetricKit은 crash/hang/CPU/disk 진단 개수만 저장한다. 원본 페이로드는 내보내지 않는다.
전체 크래시 스택은 TestFlight/Xcode와 해당 빌드 dSYM을 이용한다.

멈춘 즉시 시각과 동작(다음 파일, seek 등)을 메모한 뒤 종료하고 다시 실행한다.
파일의 마지막 세션, operation.end가 빠진 호출, app.main_unresponsive와
playback.stalled의 순서를 확인한다. 공개 GitHub 이슈에 첨부하지 않는다.
개발자가 직접 받은 파일은 해당 문제 해결 후 30일 이내 삭제한다.

## 2026-11-10 · iPhone SRT/탐색 복구

### 변경

- 공통 NetworkSubtitleLoader: URL별 동시 다운로드 합침, 24시간 TTL·64MB 예산·파일 16MB 제한.
  캐시 경로에 원본 파일명을 넣지 않는다. DSM entry.cgi 주소도 목록의 `.srt` 형식을 보존한다.
  HTTP 200 로그인 HTML처럼 파싱 실패한 캐시는 제거해 다음 선택 시 다시 받는다.
- iOS: SRT 전체를 한 번 파싱하고 현재 시각-싱크 지연으로 활성 문장을 조회한다. 과거/문장 중간
  탐색·겹친 문장·실제 빈 구간을 처리한다. 화면 비율·자막 크기를 반영하고 네이티브 자막과 중복시키지 않는다.
- 탐색 큐: 엔진 한 건 + 최종 대기 위치, 세션/요청 토큰, 네이티브 완료 콜백·시계 폴백·10초 제한.
  VLC 썸네일 취소도 전달해 탐색 후 별도 네트워크 디코더가 남지 않게 한다.
- `playback.seek_requested/begin/call_returned/recovered/rejected/timeout`의 숫자 sequence,
  source(1=네이티브 완료, 2=시계 폴백, 0=거절, 3=시간 초과), target/seconds/drift/milliseconds.
  setter 반환이나 시계 복구를 영상 프레임 출력 완료로 표현하지 않는다.
- `subtitle.cache_hit/miss`, `prepare_begin/ready/failed`, `cue_changed/resync/overlay_updated`.
  세션 UUID와 탐색 순번으로 연결하고 문장 인덱스·개수·문자 수만 기록한다. 원문/경로/주소/인증은 제외한다.
  재생 정체 감시는 낙관적 UI 위치가 아닌 실제 엔진 시계를 사용한다.

### 검수 방식과 범위

- 승인된 iPhone 13 mini만 사용한다. Synology 드라마 하위의 사용자 지정 작품으로 한정하며
  테스트 제목은 실행 환경 변수로만 전달한다. 세 지점의 문장 중간을 앞·뒤로 총 6회 탐색한다.
  자막 파일이 영상보다 긴 경우 검수 목표는 실제 영상 범위의 문장으로 제한한다.
- 공개 합성 영상: 120초·960×540·24fps 밝은 격자 MPEG-4/AAC + 알려진 12개 SRT 문장.
  NAS의 개인 영상으로 화면 배치를 검수하지 않기 위한 별도 통제 자료다. 네트워크 양쪽,
  네트워크 영상+로컬 SRT, 모두 로컬의 3조건×6회. 문장 값 일치와 완료 후 중앙 검은 픽셀 비율을 검사한다.
- 기존 빌드와 동일 조건의 전/후 비교는 하지 않았다. XCTest 탭·유휴 대기를 포함한 복구 측정값은
  순수 네트워크 지연이 아니다. 완료 후 스크린샷은 탐색 도중의 한 프레임 깜박임까지 배제하지 못한다.
- 공개 격자 캡처에서 로컬 SRT 이중 렌더링을 발견해 자동 발견 제한+트랙 변경 시 단일 선택으로 수정했다.
- QA 진입/숫자 텔레메트리는 명시적 플래그가 있는 Debug에서만 동작하고 Release에는 없다.
  통제 검수는 `TEST_RUNNER_GLAZE_RUN_SEEK_AUDIT=1`, NAS는 `TEST_RUNNER_GLAZE_NAS_AUDIT_TITLE`
  승인 제목이 있어야 실행된다. 기본 전체 테스트에서는 두 수동 검수를 건너뛴다.
- XCTest 자동 로그/실패 첨부에는 개인 영상 이름이나 프레임이 들어갈 수 있어 `/tmp`에만 보관한다.
  NAS 원시 결과를 Git/공개 보고서로 복사하지 않는다. 앱에서 사용자가 내보내는 숫자 진단과 구별한다.

### 수동 검수 준비

공개 통제 검수는 앱 Documents/GlazeSeekAudit에 `probe.mp4`, `probe.ko.srt`, `fixture.json`을
기기 복사로 준비한다. fixture.json은 `videoURL`/`subtitleURL`의 http(s) 주소 두 개만 가진다.
원격 제어 URL 스킴이나 네트워크 수신기는 앱에 추가하지 않는다. 시험용 HTTP 서버는 공개 두 파일만
읽기 전용으로 제공하고 영상의 Range 요청을 지원해야 한다. 영상은 밝은 `0x4080c0` 배경 격자,
자막은 0/10/…/110초부터 9.8초씩 `PROBE_00 · cached SRT` … `PROBE_11 · cached SRT`로 만든다.
빈 구간은 의도된 자막 공백이다. 파일/서버는 출시 앱에 포함하지 않는다.

GlazeiOSUITests 스킴에서 `ControlledSubtitleSeekTests`와 `SubtitleSeekNetworkTests`만 선택 실행한다.
전자는 탭/드래그 및 자막 끄기/복원을, 후자는 승인 작품 하위에서 SRT 메타데이터가 있는 파일을
선택한다. 긴 NAS 영상은 한 화면 포인트에 여러 초가 대응하므로 목표와 실제 착지 시각을 기록하고,
실제 착지의 문장/공백과 UI 표시를 비교한다. 존재하지 않는 자막을 기다리는 것을 지연으로 오판하지 않는다.
