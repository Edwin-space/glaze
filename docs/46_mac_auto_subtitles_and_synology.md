# 맥 — 내 언어 자막 자동 처리와 시놀로지 로그인

작성일: 2026-09-16

영상을 열었을 때 자막이 이미 준비되어 있어야 한다는 것이 이 제품의 전제다(`README`).
맥에서 그 전제가 두 군데서 무너지고 있었다.

1. 한국어 내장 자막이 있어도 그것을 고르는 일은 조용히 되고 있었지만, **없을 때** 할 수
   있는 일(다른 언어 자막을 번역)은 자막 패널을 열고 버튼을 눌러야만 시작됐다. 패널을
   여는 사람은 드물다.
2. NAS 연결이 WebDAV뿐이었다. WebDAV는 DSM에서 패키지를 설치하고 켜야 한다. 아이폰은
   `docs/35`부터 DSM에 직접 로그인해 왔다.

## 1. 자막 — 열었을 때 결정한다

### 이미 있던 것

`SubtitlePreparationPlanner`가 내장 자막을 읽고 셋 중 하나를 고른다: 내 언어 자막을
그대로 쓰기 / 다른 언어 자막을 번역하기 / 음성에서 만들기. 언어 우선순위는
`번역할 언어` 설정과 시스템 언어 순서다. 그래서 **한국어 내장 자막이 있으면 예전부터
자동으로 선택**되고 있었다. 이번에 바뀐 것은 없다.

### 바뀐 것 — 없을 때 묻는다

계획이 "번역하기"로 나오면 영상을 연 순간 한 번 묻는다.

| 답 | 하는 일 |
|---|---|
| **보면서 번역하기** | 바로 재생하고, 번역이 끝난 줄부터 화면의 자막을 갈아 끼운다 |
| **번역하고 보기** | 재생을 멈추고 전체를 번역한 뒤 다시 재생한다 |
| **원본 자막으로 보기** | 아무것도 하지 않는다. 패널의 번역 버튼은 그대로 있다 |

"이 선택을 기억하고 다시 묻지 않기"를 켜면 `설정 → 번역 → 내 언어 자막이 없을 때`에
저장되고, 거기서 언제든 `물어보기`로 되돌릴 수 있다. 묻는 것이 기본값이다. 두 시간짜리
영화의 번역은 몇 분이 걸리는 일이라, 말없이 시작해도 말없이 넘어가도 둘 다 틀렸다.

### 실시간 적용

번역 엔진은 문장 단위로 돌고 있었고 진행률(`onProgress`)만 밖으로 내보냈다. 그것을
`onSegment(위치, 번역문)`으로 바꿨다. 진행률은 위치에서 나오고, 끝난 문장은 바로 쓸 수
있다. 보면서 번역할 때는 문장 8개마다 자막 전체를 다시 조립해 화면에 올린다 — 한 줄마다
다시 만들면 영화 전체의 자막을 초당 몇 번씩 재조립하게 된다.

아직 번역되지 않은 줄은 원문 그대로 남는다(`SubtitleTranslationAssembler`가 원래 그렇게
동작한다). 중간에 멈추면 원문 자막으로 되돌린다 — 두 언어가 섞인 채로 두지 않는다.

### 확인한 것

프랑스어 내장 자막(ASS)만 있는 영상을 열어:

- 제안 창이 뜨고 문구가 맞는다
- **보면서 번역하기** — 재생이 계속되고, 진행률이 오르는 동안 한국어 줄이 화면에 올라왔다
- **번역하고 보기** — 재생이 멈췄고(프레임 6초간 동일), `번역 중단`을 누르자 다시 재생됐다

## 2. 시놀로지 — 주소 대신 호스트 이름

`설정 → 네트워크`에 시놀로지 카드가 생겼다. DSM 계정으로 로그인하고, 공유 폴더를 고른다.
NAS에서 켤 것은 없다. 로그인·브라우징은 아이폰·애플TV와 같은 `SynologyClient`와
`NetworkFolderReader`를 쓴다. 폴더 하나에 요청 하나다.

주소는 URL이 아니라 **호스트 이름 + 도메인**으로 받는다.

```
호스트 이름  my-nas
도메인      .synology.me  ▾   (.myds.me / .diskstation.me / .dscloud.me / 직접 입력)
            https://my-nas.synology.me:5001
```

DSM의 외부 접속 → DDNS를 켠 사람은 저 두 가지를 거기서 골랐다. 그것을
`https://...:5001`로 다시 옮겨 적게 하는 것은 이미 한 일을 반복시키는 것이고, 사람들이
틀리는 곳이 정확히 스킴과 포트다. 조합한 결과는 입력하는 동안 아래에 그대로 보여준다.
DDNS 이름에는 시놀로지가 발급한 인증서가 붙어 있어 **검증이 정상으로 통과**한다 —
IP로 접속해 인증서 경고를 만나던 문제(`docs/34`)가 애초에 생기지 않는다.

`직접 입력`을 고르면 예전처럼 주소를 통째로 적는다. 사내망의 IP나 5000 포트처럼 DDNS가
아닌 경우가 있기 때문이다.

세션은 앱이 들고 있는 동안만 유효하므로, 네트워크 미디어 화면에서 NAS를 고를 때마다
키체인의 비밀번호로 다시 로그인한다.

### 확인한 것

새 연결 화면에서 도메인 기본값이 `.synology.me`이고, `test-nas`를 적으면
`https://test-nas.synology.me:5001`이 표시되며, `직접 입력`을 고르면 주소 입력으로
바뀌는 것까지 확인했다. **실제 NAS 로그인과 폴더 열기는 확인하지 못했다** — 계정
비밀번호는 사용자만 넣을 수 있다.

## 3. 곁가지로 정리한 것

- 시놀로지 오류 문구가 아이폰과 맥 두 곳에 따로 있었다 → `SynologyErrorMessage`로 합쳤다
- `PlaybackController`에 `pause()`/`play()`를 넣었다. 번역을 기다리는 동안 재생을
  멈췄다가 있던 그대로 돌려주려면 `togglePlayback()`만으로는 상태를 알 수 없다

## 4. 아직 하지 않은 것

- 아이폰·애플TV에는 이 제안이 없다. 자막을 만드는 일은 맥의 몫이라는 역할 분담
  (`docs/32`)을 그대로 두었다
- 실제 NAS 로그인·폴더 열기 확인 (사용자)
